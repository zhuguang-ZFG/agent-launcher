Windows 原生配置窗口 + Windows Terminal 分屏。默认只启用一个 Agent；同项目多项使用独立 Git worktree，或明确选用现有目录/共享目录。

本机现有入口为 `artifacts/preview-claim-recovery/AgentLauncher.App.exe`，版本与对应 CI 记录见包内 `verification.json`；分发包按提交号保存为 `artifacts/AgentLauncher-preview-<提交号>.zip`。请保留同目录所有 DLL、Worker 和 runtimeconfig 文件。其他电脑需要 .NET 8 Desktop Runtime x64、Windows Terminal、所选 CLI；自动 worktree 需要 Git。此包不是自包含安装包，也不是已经完成长时负载验证的稳定版。
当前机器桌面已有 **多 Agent 启动器** 快捷方式（`D:/Desktop/多 Agent 启动器.lnk`）。版本切换需先核对活动 Worker，不能覆盖正在运行的包；完整候选和回退路径见实现记录。资源不足可选择按资源依次启动并等待，启动器不会绕过保护强行运行。
本轮另生成 `artifacts/spec-candidate/AgentLauncher.App.exe`（win-x64 自包含技术预览，内含 .NET 8.0.25）。仍须保留整个目录，外部 Git / Terminal / CLI 不内置；尚未签名或通过完整发布验收。当前验证范围与限制见实现记录第 8 节。

1. 拖入项目文件夹，或点“选择文件夹”。
2. 勾选本次项，选择 Pi/Codex/Omp/Kimi/Qoder 等。启动器自动查找 PATH 与常见安装目录；详情中的程序路径可下拉选择或浏览。参数逐项添加、移除、调整顺序，空参数和参数内换行按原值保留。
3. 选择目录策略并查看本次布局和资源检查。希望分批执行时点「按资源依次启动」：默认只执行本次勾选项，本批次并发为 1，已有等待项保持暂停、原全局并发设置保留；也可在确认框明确选择整个队列。资源不足时等待，有余量再创建工作目录和 Agent。原「启动」保留整批立即启动流程，两个入口都不会降低保护门槛。
4. 点启动后，所选 CLI（含 Omp）在对应窗格内自动加载，无需再输入启动命令；未安装或未登录的 Agent 不会自动下载安装或登录。查看逐项回执，在 Windows Terminal 内工作；启动进程不代表 Agent 已就绪或任务完成。
5. “工作目录”可查看分支/基线、打开目录；完成后人工审阅、提交、合并和测试。
6. 保存组合时可选“绑定当前项目”或“通用组合”；通用组合继承新项目，但原本单独指定的目录需要重新选择，不会自动降为共享模式。
7. 设置提供主题、100/125/150% 文字与控件大小、最近项目/组合管理及诊断预览。诊断默认隐藏完整路径，始终不导出参数、环境变量或对话。
8. 保存失败时使用「重试保存」；成功落盘前不会启动。启动中「停止后续步骤」会撤销尚未领取的请求，已运行任务保留。运行记录始终显示活动项；「全部历史与导出」可搜索保留的尝试，查看、复制和导出单条诊断。

「按资源依次启动」只有明确选择「整个队列」才会同时执行已有等待项，并把全局并发设为 1；默认批次范围会保存，重开后点「继续执行」仍只继续上次批次。「执行队列」明确执行全部未暂缓的等待项。同仓库的独立目录项仍各自使用 worktree。队列按优先级与入队先后显示实际次序；未领取的阻塞项可暂缓，其他独立任务继续，恢复后保留原顺序。关闭窗口时会提示剩余等待项，重新打开不自动派发。队列为空且无运行项时停止轮询。

活动任务上限仍为 200 张，已结束或尚未执行的卡片可「归档」释放名额；排队、执行中或结果未知的任务须先核对。归档保留身份与历史，可在「已归档」筛选中恢复；总保留卡片 1200 张、任务尝试 1000 条，达到边界会停止新增而非删除证据。任务说明和验收要求不会自动发送给 Agent，使用「复制任务说明」预览并粘贴到对应终端。登记与续接对话框提供各 CLI 的会话标识指引，续接默认只执行本任务。

`tasks.json` schema 3 增加归档、暂缓和执行范围。schema 1/2 仅在内存迁移，正常保存才写入 3；旧版会拒绝新文件，不能用旧 Worker 接管。
队列预约领取已持久化到 `control.json` schema 3：同一队列项不会因双客户端或 monitor 重启获得第二个预约；相同计划重试只返回原记录。领取证据不随历史裁剪消失，最多保留 1200 条，达到上限会停止新队列预约。旧版 Worker 拒绝 schema 3；不要通过删除 ledger、领取记录或 `.bak` 强行回退或放行。
若提示某队列项已有领取但尚未记入任务尝试，队列会在准备目录前暂停。点等待项的「原因与恢复」核对原尝试、身份档案与回执；只有可验证的终态才允许明确重新入队，并保留原次序、领取与历史。单独的 Finished 回执或记录缺失不证明已结束。未知尝试继续占用，不能删除领取记录放行。
任务来源的失败记录须从任务卡重新入队，继续遵守队列并发和尝试记录；普通快启的已确认未启动项仍可单项重试。任务主文件缺失或损坏时队列停用，可在顶部「恢复与诊断」核对备份数量并明确恢复；原文件和备份保留，恢复后仍暂停。
识别为 Node shim 的 CLI 现在同时核对运行时、入口脚本及最近包信息。升级后旧排队项可从「原因与恢复」核对后重新入队；续接项需重新核对原会话。旧版仅绑定 node.exe 的会话指纹不会自动升级，也不能据此续接旧会话。请使用同一目录内配套 App、Worker 和 DLL，并在旧 Worker 及未知尝试核对完成后再切换入口。

没有任意 shell 命令拼接入口，没有自动合并、清理 worktree 或结束用户其他程序。关闭配置窗口不主动结束已运行 Agent；关闭 Terminal 窗格仍可能结束其中任务。

实际 Terminal 窗格使用统一深色配色、稳定的「序号 / Agent / 项目」标题和一次性加载提示；双项支持左右或上下等分，多窗格打开时最大化并将焦点放在第一项。高对比度保留系统/用户配色，不改 Terminal 全局设置。美化不增加 WebView、额外 shell、常驻渲染进程或刷新动画；关闭配置窗口可释放 GUI 开销，轻量 Monitor/Runner 继续保护已启动会话。

构建：`powershell -NoProfile -File scripts/build.ps1`。发布先在新目录完成，再核对生产程序集无测试标记、文件哈希与运行时；已有包使用中会拒绝替换，成功替换时保留旧目录。

完整解压发布包后双击 `Start-AgentLauncher.cmd`；配套 `Launch.ps1 -CheckOnly` 可单独检查文件版本与 .NET 8 Desktop Runtime x64。缺失文件、混用 App/Worker、运行时缺失均给出明确原因；不会自动安装依赖。直接启动 App.exe 仍可用，前置检查由上述入口提供。

开发验证：`powershell -NoProfile -File scripts/test.ps1`。测试构建使用隔离临时目录、短生命周期进程，包含故障注入和模拟准入采样；会短暂打开双窗格及 16 窗格测试。Pi 版本检查使用临时配置目录，不写入用户配置。旧测试监控器占用默认构建目录时，可用 `-RuntimeDirectory artifacts/test-runtime-<唯一名称>` 指定新目录。该测试模式不编入 preview 生产配置。不要用测试目录的 exe 日常运行。

历史 CR01～CR12 修复见[实现记录](docs/IMPLEMENTATION.md)第 10～12 节；这些章节的数量与发布路径是当时结果。后续审查、修复和验收见第 32 节起的记录，旧 `artifacts/preview` 与第 8 节自包含包不包含本轮修复。新增回归仍待独立审查；operator `task_verify` 未有可用基线，手动检查结果不等于完整 spec 验收。


源码使用 .NET BCL/WPF，没有引用第三方 NuGet UI 库。Git、Terminal 和各 CLI 是用户已有的外部程序，不随包复制。工具默认在 `%LOCALAPPDATA%\AgentLauncher` 保存配置、备份、授权记录及准备目录；不会自动删除工作目录或计划，控制账本的已结束历史按大小上限裁剪。配置中参数按本地执行需要保存，请勿在参数中填写长期密钥。

S0.6 长稳验收使用 `scripts/run-soak.ps1 -OmpPath <omp.exe绝对路径> -OmpVersion <精确版本>`，要求源码已提交、已有 .NET 8 SDK / Node / Git / Omp。脚本在全新证据目录顺序发布验收器和 Worker，最多等待 120 分钟；连续三次内存采样达到原定 3.5 GiB 准入线后，先执行短校准，再执行真实双任务 30 分钟 × 3 轮。每个任务使用独立目录与配置，通过 Omp RPC 执行读写、哈希、搜索和 Git 工具；不发送模型 prompt。短校准、资源受阻、活动停滞或清理未核实都不能计作长稳通过。使用方法与证据边界见 [验收说明](docs/ACCEPTANCE.md#11-s06-长稳工具与结果判定)。
