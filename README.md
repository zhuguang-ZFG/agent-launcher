# 多 Agent 启动器 · 技术预览 v0.6（规格 v0.6.1，非稳定发布）

Windows 原生配置窗口 + Windows Terminal 分屏。默认只启用一个 Agent；同项目多项使用独立 Git worktree，或明确选用现有目录/共享目录。

本机入口为仓库根目录的 `Start-AgentLauncher.cmd`，指向固定目录 `artifacts/preview`，与现有桌面快捷方式使用同一套程序。入口会核对配套文件和运行时；请保留整个包。其他电脑需要 .NET 8 Desktop Runtime x64、Windows Terminal、所选 CLI；自动 worktree 需要 Git。此包仍为技术预览，不是稳定发布。规格修订号为 v0.6.1。已记录实现见 `docs/IMPLEMENTATION.md` §83–§84；三台同权的产品决定见 §88，操作员确认的重新挂接见 §89。发布门禁仍开放。
桌面 **多 Agent 启动器** 快捷方式可通过 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/use-validated-preview.ps1` 更新；脚本先验证包，再备份并替换入口，不覆盖正在运行的包。`-CheckOnly` 只验证。资源不足可选择按资源依次启动并等待。

1. 拖入项目文件夹，或点“选择文件夹”。
2. 勾选本次项，选择 Pi/Codex/Omp/Kimi/Qoder 等。启动器自动查找 PATH 与常见安装目录；详情中的程序路径可下拉选择或浏览。参数逐项添加、移除、调整顺序，空参数和参数内换行按原值保留。
3. 主界面只需选项目、勾选 Agent、启动；目录策略、分屏和资源明细收在「启动选项」，模板与规模预设收在「组合与批量设置」。Omp/Qoder 的上限低于 4 GiB 时可直接点「新任务上限改为 4 GiB」，把新任务改为独立 4 GiB 上限、1536 MiB 规划量；已有任务和已排队计划不会热改，需结束后重新启动或重新入队。希望分批执行时点「按资源依次启动」：默认只执行本次勾选项，本批次并发为 1，已有等待项保持暂停、原全局并发设置保留；也可在确认框明确选择整个队列。资源不足时等待，有余量再创建工作目录和 Agent。原「启动」保留整批立即启动流程，两个入口都不会降低保护门槛。
4. 点启动后，所选 CLI（含 Omp）在对应窗格内自动加载，无需再输入启动命令；未安装或未登录的 Agent 不会自动下载安装或登录。查看逐项回执，在 Windows Terminal 内工作；启动进程不代表 Agent 已就绪或任务完成。

   新版为 Qoder 增加独立的内存检查插件：资源不足时拒绝新增工具，恢复后重新判断，不覆盖已有 Hook 或权限设置。运行记录若提示「内存保护未确认加载」，不能依赖提前拦截。Qoder 1.1.89 已完成登录后的实际工具拦截、恢复、既有拒绝 Hook、同一进程继续及子 Agent 验证；持续负载的实际结果和边界见 `docs/IMPLEMENTATION.md` §57。外部验收入口为 `scripts/test-live-memory.ps1`，Qoder 场景使用 CLI 自己读取的现有登录状态及模型额度，不复制凭据。

   工具被内存检查拒绝后，「运行记录」标题会提示受影响项数，对应记录提供「复制继续提示」。等待已有工具结束或释放内存后，将提示粘贴到原终端；只请求重试明确未执行的步骤一次。下次工具通过检查后提示清除。它不是自动重试，也不代表显示时内存仍充足。Omp 18.20.0 与 Qoder 1.1.89 已加入精确版本的继续/指定会话预设，并验证退出进程后恢复同一已保存对话；Qoder 临时未保存会话不能续接。
5. “工作目录”可查看分支/基线、打开目录；完成后人工审阅、提交、合并和测试。需要释放磁盘时可点“清理目录”：仅清理没有会话占用且内容干净的 worktree，保留分支。忽略文件、游离 HEAD，以及可能隐藏修改的索引标记都会阻止清理，并提示先核对处理。
6. 保存组合时可选“绑定当前项目”或“通用组合”；通用组合继承新项目，但原本单独指定的目录需要重新选择，不会自动降为共享模式。
7. 设置提供主题、100/125/150% 文字与控件大小、最近项目/组合管理及诊断预览。诊断默认隐藏完整路径，始终不导出参数、环境变量或对话。
8. 保存失败时使用「重试保存」；成功落盘前不会启动。启动中「停止后续步骤」会撤销尚未领取的请求，已运行任务保留。运行记录始终显示活动项；「全部历史与导出」可搜索保留的尝试，查看、复制和导出单条诊断。

窗口顶部始终显示当前项目，点击可选择最近项目；目录已移动或无法访问时保留当前项目。点击「快捷操作」或按 `Ctrl+K`，可搜索操作、Agent、最近项目、活动会话和等待项；用方向键选择、Enter 打开、Esc 返回。侧栏会话和队列摘要可直接定位对应记录。`Alt+1…9` 切换前九个 Agent 配置，`F5` 重新检查启动条件；`Ctrl+O` 选项目，`Ctrl+Enter` 启动已勾选项。切换 Agent 只改变查看对象，不改变勾选。

侧栏每项前的复选框可直接选择本次要启动的 Agent，点序号或名称查看配置。新增后自动打开新项；详情旁的「⋯」提供「复制此项配置」和「重命名…」，也可用 `Ctrl+K` 搜索。复制保留程序、逐项参数、目录与备注，副本默认未勾选；请确认工作目录后使用。可给任意 Agent 起「前端开发」「代码审查」等分工名，留空恢复类型名称；名称和备注不会自动作为指令发送。

「按资源依次启动」只有明确选择「整个队列」才会同时执行已有等待项，并把全局并发设为 1；默认批次范围会保存，重开后点「继续执行」仍只继续上次批次。「执行队列」明确执行全部未暂缓的等待项。同仓库的独立目录项仍各自使用 worktree。队列按优先级与入队先后显示实际次序；未领取的阻塞项可暂缓，其他独立任务继续，恢复后保留原顺序。关闭窗口时会提示剩余等待项，重新打开不自动派发。队列为空且无运行项时停止轮询。

活动任务上限仍为 200 张，已结束或尚未执行的卡片可「归档」释放名额；排队、执行中或结果未知的任务须先核对。归档保留身份与历史，可在「已归档」筛选中恢复；总保留卡片 1200 张、任务尝试 1000 条，达到边界会停止新增而非删除证据。新建/编辑任务可选择手动交付、发送后交互、自动执行完退出；默认手动，自动方式检查当前 CLI 帮助并冻结任务说明和验收要求，续接不重发。任务内容会保存在本地记录和进程参数中，请勿填写密钥。「后台运行」收起到托盘并继续已有队列；再次打开恢复窗口。登记会话提供同工作目录的本地候选，程序升级后可重新检查并确认续接。详见[八项实用性修复](docs/USABILITY-FIXES-20261117.md)。

`tasks.json` schema 4 增加交付方式和续接程序重新核对，保留 schema 3 的归档、暂缓和执行范围。schema 1–3 仅在内存迁移，正常保存才写入 4；旧版会拒绝新文件，不能用旧 Worker 接管。
队列预约领取已持久化到 `control.json` schema 3：同一队列项不会因双客户端或 monitor 重启获得第二个预约；相同计划重试只返回原记录。领取证据不随历史裁剪消失，最多保留 1200 条，达到上限会停止新队列预约。旧版 Worker 拒绝 schema 3；不要通过删除 ledger、领取记录或 `.bak` 强行回退或放行。
若提示某队列项已有领取但尚未记入任务尝试，队列会在准备目录前暂停。点等待项的「原因与恢复」核对原尝试、身份档案与回执；只有可验证的终态才允许明确重新入队，并保留原次序、领取与历史。单独的 Finished 回执或记录缺失不证明已结束。未知尝试继续占用，不能删除领取记录放行。
任务来源的失败记录须从任务卡重新入队，继续遵守队列并发和尝试记录；普通快启的已确认未启动项仍可单项重试。任务主文件缺失或损坏时队列停用，可在顶部「恢复与诊断」核对备份数量并明确恢复；原文件和备份保留，恢复后仍暂停。
识别为 Node shim 的 CLI 现在同时核对运行时、入口脚本及最近包信息。升级后旧排队项可从「原因与恢复」核对后重新入队；续接项需重新核对原会话。旧版仅绑定 node.exe 的会话指纹不会自动升级，也不能据此续接旧会话。请使用同一目录内配套 App、Worker 和 DLL，并在旧 Worker 及未知尝试核对完成后再切换入口。

没有任意 shell 命令拼接入口，没有自动合并、清理 worktree 或结束用户其他程序。关闭配置窗口不主动结束已运行 Agent；关闭 Terminal 窗格仍可能结束其中任务。

实际 Terminal 窗格使用统一深色配色、稳定的「序号 / Agent / 项目」标题和一次性加载提示；双项支持左右或上下等分，多窗格打开时最大化并将焦点放在第一项。高对比度保留系统/用户配色，不改 Terminal 全局设置。美化不增加 WebView、额外 shell、常驻渲染进程或刷新动画；关闭配置窗口可释放 GUI 开销，轻量 Monitor/Runner 继续保护已启动会话。

物理内存不足时，Monitor 会尝试缩减连续 30 秒未观察到 CPU 活动的已启动会话工作集，让活跃任务获得更多物理余量。运行记录显示实测减少量；原数据保留，再次使用时按需载入，可能稍有延迟。每个会话至少间隔两分钟、全局至少间隔五秒并等待新采样；仅 CPU 忙或提交余量不足不会触发。此功能不降低提交占用或 Job 硬上限，不等于扩大内存容量，也不保证所有 CLI 长任务都能避免 OOM。

远程（VPS）执行：在「远程主机（VPS）」添加通过 SSH 访问的 Linux 主机后，每个槽位的 Agent 下拉都列出该主机的云候选（「Name · ☁ 主机名」），未绑定槽位也可以选；选中后绑定主机，远程目录为空时按 `~/work/<项目名>` 派生。远端进程仍在远端机器上运行，可降低本机内存占用。产品决定「三台同权」：本机、京云、阿里云对共享项目工作区同权。任一台上的 agent 都可以修改这份工作区，另外两台必须看到同一批文件。同权靠必须的双向工作区同步；远端进程没有本机文件系统的直接访问权。推荐 Mutagen。启用同步时，远端修改回到本机工作目录，可用槽位「查看改动」核对（只读 git status）。同步模式「不同步」（`None`）不是同权，各机只看见自己的目录，表现得像互相断开。规格里已有的 SSHFS 仍是原有挂载备选，不是新的三台同步机制。已实现的是 SSH 远程执行和可选的 Mutagen；选择 `None` 时这次启动不是同权。同步状态（就绪/同步中/有问题/未同步）在重启后按已保存的会话名匹配。连接全程免密：走密钥 / ssh-agent / SSH config，`BatchMode=yes` 绝不提示密码；主机卡片提供「测试免密连接」自检。侧栏、槽位与分屏预览以 🖥 本机 / ☁ VPS·主机名 徽章区分来源。主机卡片与 VPS 槽位菜单提供「检查版本 / 升级 Agent」，在本机经免密 SSH 对远端 CLI 执行升级（默认命令按 agent 推断，可在主机编辑中按 `agent=命令` 覆盖），升级前显示确切命令并二次确认。详情可只读查看远端资源。SSH 断连的远程条目保持非终止；操作员在「核对并确认释放」中判断远程进程已不在、填写原因并二次确认后才释放（R28）。断线后不会自动重连。为维持同权，连接断开时可以「核对并确认重新挂接」（R33）：确认后若远程进程仍在，则恢复同一条记录上的本地 SSH；原来启用了同步的会重新建立，选择 `None` 时不会显示成已同步。远程进程已不在则拒绝，且不会因此自动释放。远程 cgroup 与 `MemoryLimitBytes` 仍未实现；启动命令里的 `NODE_OPTIONS=--max-old-space-size=1024` 只限制 Node 堆。同时运行的 Agent 窗格最多 8 个，本机和远程都占名额：把工作放到 VPS 不腾出本地窗格；尚未在「核对并确认释放」里释放的「连接断开」继续占一个名额。内存与 CPU 准入不把远程批次算进本地压力，远端限额也不因此与本机相等。见 `docs/CONTRACTS.md` C14 与 `docs/IMPLEMENTATION.md` §88、§89。真实双 VPS 活测与发货预览包复验见 `docs/IMPLEMENTATION.md` §83–§84，不是 CI，也不是长稳，也不证明三台同权已经活测。

构建：`powershell -NoProfile -File scripts/build.ps1`。发布先在新目录完成，再核对生产程序集无测试标记、文件哈希与运行时；已有包使用中会拒绝替换，成功替换时保留旧目录。

完整解压发布包后双击 `Start-AgentLauncher.cmd`；配套 `Launch.ps1 -CheckOnly` 可单独检查文件版本与 .NET 8 Desktop Runtime x64。缺失文件、混用 App/Worker、运行时缺失均给出明确原因；不会自动安装依赖。直接启动 App.exe 仍可用，前置检查由上述入口提供。

开发验证：`powershell -NoProfile -File scripts/test.ps1`。测试构建使用隔离临时目录、短生命周期进程，包含故障注入和模拟准入采样；会短暂打开双窗格及 16 窗格测试。Pi 版本检查使用临时配置目录，不写入用户配置。旧测试监控器占用默认构建目录时，可用 `-RuntimeDirectory artifacts/test-runtime-<唯一名称>` 指定新目录。该测试模式不编入 preview 生产配置。不要用测试目录的 exe 日常运行。

历史 CR01～CR12 修复见[实现记录](docs/IMPLEMENTATION.md)第 10～12 节；这些章节的数量与发布路径是当时结果。后续审查、修复和验收见第 32 节起的记录，旧 `artifacts/preview` 与第 8 节自包含包不包含本轮修复。新增回归仍待独立审查；operator `task_verify` 未有可用基线，手动检查结果不等于完整 spec 验收。


源码使用 .NET BCL/WPF，没有引用第三方 NuGet UI 库。Git、Terminal 和各 CLI 是用户已有的外部程序，不随包复制。工具默认在 `%LOCALAPPDATA%\AgentLauncher` 保存配置、备份、授权记录及准备目录；不会自动删除工作目录或计划，控制账本的已结束历史按大小上限裁剪。配置中参数按本地执行需要保存，请勿在参数中填写长期密钥。

S0.6 长稳验收使用 `scripts/run-soak.ps1 -OmpPath <omp.exe绝对路径> -OmpVersion <精确版本>`，要求源码已提交、已有 .NET 8 SDK / Node / Git / Omp。脚本在全新证据目录顺序发布验收器和 Worker，最多等待 120 分钟；连续三次内存采样达到原定 3.5 GiB 准入线后，先执行短校准，再执行真实双任务 30 分钟 × 3 轮。每个任务使用独立目录与配置，通过 Omp RPC 执行读写、哈希、搜索和 Git 工具；不发送模型 prompt。短校准、资源受阻、活动停滞或清理未核实都不能计作长稳通过。使用方法与证据边界见 [验收说明](docs/ACCEPTANCE.md#11-s06-长稳工具与结果判定)。
