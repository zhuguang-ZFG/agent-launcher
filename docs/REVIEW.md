# Spec Review：v0.3 → v0.4

日期：2026-11-09  
审查对象：原 v0.3 产品规格，及本轮用户追加的“详细设计、多线程、电脑性能第一”要求。  
方法：单人规格审查、官方资料核对、只读硬件/内存快照、文档一致性检查。没有应用源码，因此不是已完成的源码 code review；没有调用其他 reviewer 或子 Agent。

## 1. 结论

v0.3 足以表达产品方向，但不足以直接按稳定产品实现。主要缺口不是更多功能，而是启动结果、资源保护、状态恢复和可执行验收。

v0.4 已将这些缺口写成设计合同和测试项。**所有“修复”仅指规格层面，应用实现与测试仍未执行。** 可进入有边界的 G1 技术验证；共享 Job 与 Terminal 兼容、npm shim、辅助层资源开销是实施前的关键风险，不能先假定成功再铺大 UI。

## 3. 本轮新增决策

- 默认先启用一个 Agent。双开/四开由用户选择并通过资源检查；这比固定双开更符合最新性能要求。
- GUI 使用 C# / .NET 10 + WPF/XAML；设计语言采用 Fluent 原则；界面中文；`unslop` 用于原生化视觉审查。
- 保留 Windows Terminal。新增的是小型资源监控和受控 Runner，不新增模型编排服务、Web 后端或自有终端渲染。
- 内存硬限额会让超额工具分配失败，这是保护桌面的取舍。不会把“限制内存”描述为“所有工具照常运行但更省”。
- 异常分类、Unknown 和核对恢复优先于自动重试；不自动杀正在写文件的 Agent。
- 原生 UI 截图、键盘/Narrator、DPI 和真实桌面响应性都是发布证据；HTML 设计稿只能用于讨论外观/流程。

## 4. 仍需验证的风险

| ID | 风险 / 未知 | 最迟验证阶段 / 失败处理 |
| --- | --- | --- |
| O01 | 多个 Windows Terminal 窗格下共享外层 Job 与既有 ConPTY/宿主嵌套 Job 是否兼容 | G1；不兼容先重设计进程创建/归属，不能静默取消保护 |
| O02 | NativeAOT 控制台辅助层能否同时满足交互、回执和 ≤64 MiB 预算 | G1；测量后优化/改辅助实现，界面栈无需跟着重写 |
| O03 | 真实 Pi npm shim、参数与 Ctrl+C 是否保持原生行为 | G1；未通过不宣称支持，不以简化测试 exe 代替 |
| O04 | 每会话 2 GiB、总 CPU 35% 是否适合用户典型项目 | G1/G4；报告失败任务和响应性，调整必须保持系统余量，不随意放开 |
| O05 | 外部服务、GPU/磁盘瓶颈、非后代进程不被 Job 完整限制 | G4；明确范围，受支持主任务仍卡桌面则不通过发布门槛 |
| O06 | 当前机器低内存快照不等于长期空闲状态 | G1 前重新采样；不据此强杀用户程序或直接跑压力测试 |
| O07 | 用户尚未明确要求终端一定嵌入同一应用 | 按轻量形态 A 设计；如改为 B，重新评估架构/验收，而不是称作小改 |
