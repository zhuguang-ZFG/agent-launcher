# 八项实用性修复（2026-11-17）

| 原问题 | 当前操作与行为 |
| --- | --- |
| 异常退出统一等待验收 | 非零退出显示失败及退出码，诊断保留；后代仍运行时单独提示 |
| 摘要漏新增文件、基线漂移 | 启动前固定提交，未跟踪文件单列；旧记录及共享目录说明比较范围 |
| 任务队列只打开 CLI | 新建/编辑任务选择交付方式，可发送初始任务并执行完退出；默认仍为手动 |
| 退出 GUI 就停止派发 | 任务栏“后台运行”收起到托盘，双击图标或再次打开恢复 |
| monitor/runner 丢失引起长期资源阻塞 | 独立句柄守护保留原资源组，可重新核对实际成员；无法证明的旧占用仍保留 |
| 同名终端误定位 | 完整批次身份与创建顺序定位，检查目标窗格和前台结果 |
| 详情卡在版本检查 | 表单立即打开，后台探测可取消，修改路径使旧结果失效 |
| 会话 ID 难找、升级后不能续接 | 登记时提供同工作目录的本地候选；升级后重新核对并确认程序，历史指纹不改写 |
| 清理只报“目录不干净” | 检查清理内容展示分类清单，支持刷新、复制和打开目录，再由用户处理 |

自动交付的说明会出现在本地配置、冻结启动记录和操作系统进程参数中，表单明确提示不要填写密钥。不同 CLI 的工具授权仍由其自身设置决定，自动执行不承诺跳过交互确认或替代人工验收。

会话列表最多扫描 2,000 个文件、2 秒、每文件前 64 KiB/12 行，最多显示 100 项；只读元数据，可能遗漏旧会话、特殊安装位置及未写完的记录，保留手工填写/文件选择入口。Qoder 多工作目录会话不自动归到单一项目。

旧池已失去所有句柄时，无法从“对象名称不存在”证明后代退出，仍需要系统重启后的核对。新守护提高单点故障恢复能力，不宣称任意多个进程同时丢失后仍可恢复。

实现合同见 C13，验收映射 UX12，实际执行记录见 IMPLEMENTATION §81。
