# 验收与代码 Review 计划 v0.6

状态：已开始原生/原型测试，实际结果见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。以下 51 项仍是完整发布要求，不能将已通过的子场景升级为整项通过；未被结果报告明确覆盖的条件均未执行。规格检查、颜色计算不能替代原生功能、截图或性能测试。

## 1. 发布判定

电脑响应性和数据完整性是阻断门槛。P0/P1 未关闭，或关键测试未执行，不发布“稳定可用”版本。失败必须记录复现、实际结果、修复和重测证据；不能只修改基准截图/阈值使测试变绿。

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 意外丢失工作、启动任意非预期命令、范围错误地结束进程、持续拖死桌面 | 立即停止该路径，修复并回归 |
| P1 | 重复启动、资源保护未生效、常用流程不可用、无法恢复的配置损坏、主要操作不可达 | 阻断候选版本 |
| P2 | 有可理解替代路径的次要故障或视觉/文案问题 | 修复或明确记录影响与接受理由 |
| P3 | 不影响操作的微小样式问题 | 可进入后续清单 |

每条结果至少包含：测试 ID、构建版本/提交、机器/系统、前置条件、操作、预期、实际、截图/日志/采样文件、执行者、日期、状态。状态仅有未执行、通过、失败、受阻；规格修复不填“通过”。

## 3. 故障注入与防崩溃

故障注入在临时测试仓库、测试配置目录和受控程序中进行。绝不以用户真实项目验证“会不会丢文件”，不为测试耗尽用户桌面内存。

| ID | 注入位置 | 必须断言 |
| --- | --- | --- |
| R01 | GUI 在已有 Agent 运行时崩溃 | Terminal/Agent 仍可交互；重开只核对状态，不重启 Agent |
| R02 | SubmitIntent 前、后，Terminal 提交后分别中断 | 状态对应；只有能证明未启动的项可重试 |
| R03 | 子进程创建后、Started 回执写入前让 Runner 退出 | 结果 Unknown；不重复生成进程；不误称失败 |
| R04 | 正常退出、非零退出、Ctrl+C、关闭窗格 | 退出信息准确；控制台不抢输入；不把 exit 0 当任务完成 |
| R05 | 一个窗格失败，其他成功 | 成功项保留；失败有可读信息；重试不复制整组 |
| R06 | 监控器异常退出/恢复，GUI 同时关闭 | 既有 Job 配额保持；新任务阻止直到身份与账本恢复；无重复配额组 |
| R07 | 测试进程触及内存硬限额、子进程继续运行 | 内存超额行为可解释；电脑仍可操作；主 CLI 退出不提前释放后代预算 |
| R08 | Job API 失败、旧 PID 被复用、旧系统启动记录 | 不运行未保护子进程；不操作错误 PID；旧记录不冒充当前会话 |
| R09 | 第二个 worktree 创建失败/磁盘写入拒绝 | 第一个保留且记录；主项目不变；重试不重复创建 |
| R10 | `git worktree add` 已成功、完成记录未写前中断 | 用 Git 实际状态核对后恢复，不乱删目录或再造分支 |
| R11 | JSON 截断、写入一半、未来 schema、备份损坏 | 有效备份可恢复；未来版本不降级覆写；草稿未保存状态明显 |
| R12 | 无写权限、磁盘满、日志输出失败、异步超时/取消 | 错误出口不再次崩溃；不死锁/无限重试；取消边界明确 |
| R13 | 创建时 Job 关联失败；在 CreateProcess 前/中/后、CreatedSuspended、ResumeIntent、Started 边界中断 Runner/监控器 | 无未归属挂起进程；唯一 attempt Job 可核对；只回收可证明未运行的自有进程；既有运行会话保留；不以 Unknown 代替泄漏处理 |
| R14 | 延迟 Runner，撤销 Pending 后新建请求，再放行旧 Runner；授权领取回执丢失；监控器重启 | 旧代次不能创建进程；领取/撤销只有一方成功；Creating 先核对；不超额/重复启动；撤销后预算可释放且无任务时监控器退出 |
| R15 | 受控 Git filter/hook 重负载、准备 Job 超额、目标盘空间不足 | Git 后代受保护，CPU/内存计入总量；停止新增准备、不删锁或用户目录；已有工作区可核对 |
| R16 | 目录占用者 GUI/Runner/监控器异常，主 CLI 退出但子工具存活，路径身份被替换 | 未核对前不能释放独立占用；后代归零并终结授权才释放；身份变化阻止启动；正常结束后可重用 |

补充回归：不同 DPI 屏幕之间移动、拔掉原显示器、睡眠/唤醒后的采样失效；唤醒后重新采样，不能沿用睡前资源准入。

## 4. 性能与电脑响应性

### 4.1 测量规范

- Release、自包含分发形式；记录 CPU、RAM、磁盘、Windows/Terminal/CLI 版本、电源模式、背景负载、是否云端模型。
- 区分首次/温启动，GUI/监控器/Runner/Terminal/Agent/工具分组报告。
- 使用 Private Bytes 表示私有提交开销；Working Set 另报，不把共享页简单相加后宣称物理内存总量。
- 同机对照手工运行相同两个 Agent 与应用运行，工作负载相同。分别测空闲、真实任务峰值、正常退出后的释放。
- 所有 P95 记录样本数和算法；20 次启动的 nearest-rank P95 是排序第 19 个，不用平均数冒充 P95。长周期响应性记录样本远多于 20。
- 先跑受控程序验证资源保护，再运行代表性真实任务；不在当前低内存用户桌面做破坏性压力试验。

### 4.2 测试项和初始预算

| ID | 指标 / 场景 | 验收目标 |
| --- | --- | --- |
| P01 | UI 温启动与本地目录拖入反馈 | 20 次启动 P95 ≤ 1 秒；拖入可见反馈 P95 ≤ 100 ms；后台检查可继续 |
| P02 | 空闲 GUI | Private Bytes ≤ 100 MiB；60 秒整机口径 CPU 平均 < 0.5% |
| P03 | UI 关闭、两个受管会话空闲 | 监控器 + 两 Runner Private Bytes 总计 ≤ 64 MiB，CPU 平均 < 0.2%；不隐藏辅助进程 |
| P04 | 低内存/低提交余量、CPU 忙、多请求同时准入 | 不超额预约；阻止新增但 UI 可交互；恢复需稳定采样且不自动启动 |
| P05 | 两个 CPU 压力进程及孙进程，持续 60 秒 | 受管总 CPU 在配置 35% 上限附近且不随窗格翻倍；采样误差允许至 40%，原始数据保留；Terminal 未被限速 |
| P06 | 内存压力与限额、磁盘密集工具 | 限额能约束受管提交；主程序/工具失败有反馈；不能造成持续桌面卡顿；磁盘行为不合格同样阻断发布 |
| P07 | 实际双 Agent、编译/测试期间的交互 | 启动器输入响应 P95 ≤ 100 ms、单次 ≤ 500 ms；Windows 窗口切换、资源管理器、终端输入重复操作无连续 > 1 秒冻结 |
| P08 | 30 次受控启动/退出 + 2 小时空闲存活 | 无孤儿 Runner/监控器；Job 清空后监控器 ≤ 5 秒退出；返回基线后的额外内存不持续线性增长，净增目标 ≤ 10 MiB；句柄无持续增长 |
| P09 | 已有 Agent 工作时准备另一个大测试仓库；多个仓库同时请求准备 | 全局最多一个准备操作；Git + Agent 合计 CPU/内存预算有效；不另给 Git 一份 35%；磁盘余量被检查；准备期间同样满足 P07 响应目标 |

P07 的 UI 延迟由事件/呈现时间戳测量，桌面交互用录屏或 ETW/同等可复查证据补充。不能用“肉眼感觉流畅”作为唯一证据，也不能仅测应用内部按钮而忽略整机。

需覆盖实际用户机器的受控负载，以及内存约 8 GiB、4 个逻辑处理器的资源受限测试环境。虚拟机可验证故障边界，不替代真实机器 GPU/驱动/DPI 行为。如果受限环境只能可靠单开，发布能力表必须明确，不承诺四开。

Terminal 进程提交后窗格出现目标 P95 ≤ 3 秒，单独计时；完整流程还要记录资源采样、Git 检出、CLI 初始化耗时，不能把它们全部排除后宣传“一秒全部启动”。

速度评价包含任务完成、人工整合与测试。CPU 限速可能让编译慢一些，这是保护桌面响应性的明确取舍。性能不达标时先减并发/优化辅助层，再扩展功能；阈值调整必须写理由和重新测量。

### 5.2 人类使用验收

找未参与实现的人执行；如果只能开发者自测，明确标为“自测，尚无独立可用性验证”。不要求用户读实现合同才能用应用。

| 任务 | 目标 |
| --- | --- |
| 第一次启动一个 Pi | 在 CLI 已安装/资源满足前提下，不输入 shell 命令，60 秒内完成配置与提交 |
| 再次启动同项目/新项目 | 组合已保存后，选中/拖入项目加一次启动动作；合理错误不会要求重填全部配置 |
| 两个 Agent 同项目隔离 | 能说清“目录独立、修改后要合并”，无需先学会 worktree 命令 |
| 遇到内存不足 | 能从界面判断为什么不能启动、可做什么；不会误以为软件死机 |
| 部分失败与 Unknown | 能找到已有终端与失败项，避免重复启动；不能把“重试”理解成结束已有任务 |
| 关闭窗口 | 能区分关闭配置窗口、关闭终端、正常退出 Agent 的结果 |

记录误点击、找不到入口、焦点丢失、需要口头指导的步骤。以上任何主任务需反复解释，返回设计修正；不能只靠截图好看来接受。

## 6. 代码 Review 门禁

已有四层应用源码，本轮完成编译、运行回归与自审，问题/修复记录见 IMPLEMENTATION。后续每一阶段的最终 diff 都要 review；测试通过不代替代码审查，也不把自审称为独立审查。

| 审查面 | 必须检查的问题 |
| --- | --- |
| 线程/异步 | UI 是否同步等待？取消是否真实可执行？是否泄漏 Task、事件订阅、计时器或无界队列？ |
| 资源保护 | 创建时 Job 关联是否有效？Git 准备及其后代是否计入总额？总配额是否被每格重复授予？后代进程、嵌套 Job、失败清理是否正确？ |
| 生命周期 | 授权撤销与领取是否原子互斥？创建阶段是否可归属恢复？GUI/监控器崩溃是否触发 kill-on-close？是否误重试 Unknown/用过期 PID？ |
| 命令边界 | shell 多层解析、npm shim、Terminal 分号、cwd/argv 是否精确？是否不可信项目路径变成命令？ |
| Git | 是否身份去重、固定基线、保留脏内容、处理部分成功？目录占用是否覆盖跨批次/子目录/别名及后代进程？是否意外 stash/删除/改全局设置？ |
| 持久化 | 单写者、revision、原子替换、备份、schema、日志上限是否与合同一致？ |
| UI | agentId/profile/程序参数是否一致？模板是否完整深拷贝？LastEdited 是否有独立快照？应用/取消是否事务化？焦点、错误恢复、缩放与 UIA 是否对应设计？ |
| 测试 | 是否断言外部行为和失败边界？是否只测试“代码照着写了一遍”的同构逻辑？ |
| 发布 | 自包含真实包能否运行？依赖/许可证是否锁定？有无安装路径、权限或更新覆盖活动 Runner 的问题？ |

问题记录格式：`ID / 严重度 / 文件:行 / 触发步骤 / 用户影响 / 建议修复 / 验收测试 / 状态`。没有真实触发路径的假设标为风险，不伪装成已复现 bug。

修改者可以先自审，但不能把自己的重复阅读描述成“独立审查”。有其他开发者时安排第二人；若用户明确授权多 Agent review，再启用隔离的 reviewer。本轮未调用子 Agent。

## 11. S0.6 长稳工具与结果判定

`tests/AgentLauncher.Soak` 为验收程序，使用 .NET 8 BCL，通过真实 monitor `reserve/run` 启动两个独立任务。它不随生产预览分发。`scripts/test.ps1` 编译它，并通过原生 harness 检查其参数、路径、计时、活动检测和 RPC 失败边界；这些检查不计作正式长稳轮次。

在干净工作树执行：

```powershell
powershell -NoProfile -File scripts/run-soak.ps1 -OmpPath 'C:\path\omp.exe' -OmpVersion '18.19.0'
```

可指定 `-NodePath`、`-GitPath`、`-WaitMinutes 1..120` 和 artifacts 下不存在的 `-EvidenceDirectory`。工具必须由使用者安装；脚本不安装运行时、CLI 或依赖。不要从带模拟采样或测试根环境的进程调用它。原定双任务物理余量为 2 GiB + 2 × 768 MiB；等待结束仍不足时只写受阻结果，不启动负载、不结束其他进程。每轮还须通过真实资源策略的 CPU、commit 和软预算检查。

| 阶段 | 必须核实的证据 |
| --- | --- |
| 版本与隔离 | 精确 Omp 版本、工具/运行时 SHA-256、加载 DLL 与 Worker 一致；全新普通路径；不使用用户配置或继承凭据。 |
| 校准 | 单独 20 秒双任务轮次；报告 mode=calibration，stability.eligible=false；不纳入长稳计数。 |
| 正式轮次 | 固定 3 × 1800 秒；两个 driver 均 ready 后开始单调计时；全程 Worker/monitor/Job 存活可查询；工具活动持续且计数不倒退。 |
| 停止与清理 | 双方观察停止文件，Omp/Worker/Finished 全部 exit 0，实际 Job 上限 2 GiB、峰值可读且大于零、成员归零；自有 monitor 停止、日志排干、cleanup.verified=true。 |
| 最终结论 | 三轮全部满足且最终 status=succeeded、无失败或清理错误，才可写 stability.eligible=true。任何短轮、缺失证据、强制终止或未知退出不得通过。 |

`supervisor.json` 原子记录等待、校准、正式执行或停止状态，`memory-samples.jsonl` 保存逐次真实余量；独立根下的 `soak-result.json` 包含每轮采样、工具计数、回执、峰值及清理记录。Ctrl+C 要求验收器收尾；若进程被强制结束，应按原有账本/Job 核对，不能从报告缺失推断完成。日志按字符数有界，JSON 读取上限 8 MiB。

该负载验证 Omp RPC 工具与 Launcher 生命周期，不涉及模型推理；Omp 启动可能刷新公共模型目录。它不代替两小时真实中文交互 CLI、生产 F12 的人工交互、无障碍、干净环境分发或 S5 多会话隔离/收益验收。失败请求不重放，无法证明退出时保留占用与文件。
