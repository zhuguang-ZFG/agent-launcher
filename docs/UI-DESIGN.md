状态：完整设计合同，已有 [离线可点击设计稿](prototype.html) 和 WPF 技术预览。主范围见 [SPEC.md](SPEC.md)，实现与截图见 [IMPLEMENTATION.md](IMPLEMENTATION.md)，完整验收见 [ACCEPTANCE.md](ACCEPTANCE.md)。

HTML 仍用示例数据，只用于说明交互；其 3 项已知配置缺陷已通过 5 组模型测试和 5 项 Edge 实际点击断言。WPF 已实现目录选择/拖入、配置增删上移、模板、命令探测、资源和逐项状态、工作目录查看与备份恢复。

**版本边界：原生有 125% DPI 的浅/深/窄窗口截图和 13 项控件/布局断言，尚未完成所有 DPI、Narrator、独立视觉和可用性验收。当前布局将最近项目置于下拉列表，参数采用每行一个，目录策略直接选择；完整设计中的拖动重排、独立参数行按钮等细节见实现差异表。**

## 1. 方向、技能和实现语言

采用 Windows Fluent 的控件与行为习惯，面向经常启动 CLI 的 Windows 用户。实现为 C# + WPF/XAML；界面简体中文；路径、Agent 和命令保持原文。

五行设计方向：

- 产品：拖入项目、选好组合，在受控资源预算内启动多个 Agent。
- 性格：克制、明确、可预期。
- 场景：桌面开发工具，像一个配置准确的终端启动面板。
- 重点：本次实际布局、实际启动数量、资源准入结果；让人一眼判断接下来会发生什么。
- 识别细节：配置项的序号与终端布局位置一一对应，始终使用同一名称。

`unslop` 用于视觉方向与逐层审查，适配其间距、颜色、图标、文案、字体、布局、细节和动效方法。原生应用遵循系统可访问性，不强行使用 skill 的网页尺寸、Lucide、hero、大图片或装饰性“亮点”。等大的终端预览格有明确业务意义，不因视觉建议而改成不规则卡片。

本文件对 `unslop` 方法有适配，来源：Damir Sokolovsky（[@heydamir](https://x.com/heydamir)），[unslop](https://heydamir.design/unslop)，CC BY 4.0。其他代码和第三方控件的许可证分别记录。

只有一个主窗口，附带按需打开的侧栏/对话框。第一屏不放统计大盘、实时折线或大量设置。

| 页面 ID | 内容 | 进入方式 |
| --- | --- | --- |
| U01 | 项目、Agent 配置、布局预览、启动 | 主窗口 |
| U02 | 选择 Agent / 自定义命令 | 某项的 Agent 选择器 |
| U03 | 同项目目录策略与分工说明 | 同仓库多项启用时的目录设置 |

## 3. U01 主窗口

首选尺寸 1040 × 720 DIP。恢复窗口时按当前屏幕工作区夹取，四边留出可见空间；不能把旧屏幕坐标直接恢复到已拔掉的显示器。宽度低于 840 DIP，最近项目改成下拉入口；配置列表与预览上下排列。低矮窗口只滚动内容区，标题和底部主操作保留。

不强制 760 × 520 的全局最小尺寸：在 1366 × 768、200% 缩放等有效工作区不足的场景，最小约束也必须随工作区缩小。文字不整体缩小来塞进屏幕。

### 3.1 配置列表与预览

- 最多四项；“添加 Agent”到达上限后禁用，提示“最多保存 4 项”。
- `本次` 复选框控制是否产生进程；未启用项可编辑，不参与 CLI/目录启动校验，不消耗实例预算。
- Agent 选择器显示名称与命令状态。参数默认收起；未开启参数也能完成主流程。
- 名称固定对应配置 ID。重排后按新的顺序更新位置编号；保存计划后不能被正在编辑的 UI 改写。
- 重排有拖动手柄，也有菜单“上移 / 下移”；移除配置不结束已经运行的会话。移除后可立即撤销。
- 目录默认继承项目；单项覆盖后显示“独立指定目录”和完整路径入口。重置为继承必须有显式按钮。
- 本次预览只显示启用项：1 项单格，2 项左右/上下，3 项左一右二，4 项四格。零项时没有空终端预览，显示“选择至少一个 Agent”。
- 例如启用第 1、4 项，预览标签仍显示“1 Pi / 4 Hermes”，实际位置由有序映射决定，避免把配置项 4 错认成配置项 2。
- 预览是配置示意，无闪烁光标、伪造终端输出或“运行中”绿点。

### 3.2 拖拽与替代操作

| 操作 | 行为 |
| --- | --- |
| 单目录拖入顶部 | 更新默认项目，所有继承项一起更新，覆盖项保留 |
| 单目录拖入某项的目录区 | 只更新该项；接收区域高亮并显示“替换此项目录” |
| 多目录拖入顶部 | 按系统给出的顺序填入，用户可重排；不静默开启未启用项；显示“已填入 3 个项目，本次启动 1 个” |
| 超过剩余容量或混入普通文件 | 整次不应用，说明数量/类型问题；不部分接收后隐藏遗漏 |
| 最近项目单击 | 作为默认项目，不直接启动 |
| 拖入 URL、文件、不可访问目录 | 保持原配置，显示对应原因 |
| 完全不用拖拽 | 用“选择文件夹”、可编辑路径输入、重排菜单完成同样操作 |

有效拖拽目标显示文本和边框，不只改颜色；离开立即恢复。目录不存在、权限不足分别提示。路径输入只在失焦/提交时完整验证，避免每次键入都触发磁盘检查；异步结果带版本号，旧结果不得覆盖新输入。

默认不以管理员身份运行，避免与资源管理器权限不同导致拖入失败。若外部方式强制提升，说明拖拽可能不可用，文件夹选择器仍可用。

### 3.3 键盘和焦点

- `Ctrl+O` 选择默认目录，`Ctrl+Enter` 仅在主窗口且验证满足时启动。
- Tab 顺序：组合 → 项目入口 → 配置列表 → 布局 → 目录策略 → 资源详情 → 保存 → 启动。
- 列表内按常规控件行为操作；按钮支持 Enter/Space；下拉框支持搜索、箭头、Enter、Escape。
- 自定义参数编辑或模态窗口打开时，`Ctrl+Enter` 不穿透触发主启动。
- 对话框关闭后焦点返回触发控件；错误后聚焦第一个需要修复的字段。
- Escape 关闭菜单/对话框，主窗口中不直接退出应用或中止 Agent。
- 后台探测完成不抢焦点；用户在终端输入时不弹出强制前台窗口。

## 4. U02 Agent 选择与命令编辑

选择器顺序：最近使用 → 已找到命令 → 未找到预设 → 自定义 Agent。搜索按名称过滤。

预设 Pi、Claude Code、Codex、Gemini CLI、OpenCode、Hermes、Omp、Kimi、Qoder。标签只显示真实证据：“找到命令”“未找到”“版本未验证”。不能因为存在同名文件就显示“已登录”。

自定义编辑字段：名称、程序路径（浏览按钮）、参数列表（增加/删除/上下移动）、执行类型（自动解析后的可读结果）。不提供默认的任意 shell 脚本大文本框。预设也允许指定实际安装路径。
参数编辑以数组项为边界，不用换行文本拆分数组；空字符串、参数内换行、中文/空格和尾部反斜杠在“打开→应用”后必须保持相等。程序路径始终可编辑，下拉候选合并本机发现与当前配置的手动路径；没有发现结果也能直接输入。Qoder CLI 预设使用 `qodercli`，不能把 `qoder` IDE/CLI 分发脚本直接当作受支持 shim。


“检查命令”只验证解析和支持的执行类型，不擅自运行任意程序获取版本。需要执行版本探测时只对明确适配的 CLI 使用固定命令并显示动作。添加 CLI 不自动安装、授权或联网登录。

错误示例：`未找到 pi 命令。选择安装位置，或更换 Agent。` 提供“选择程序”和“重新检查”。支持类型以合同 C1 为准；不把 PowerShell 函数/别名当成普通可执行文件。

防护交互：切换 Pi → Codex 时同时切换名称、对应程序位置、参数、探测状态；保留 Pi 自己的历史设置供切回使用，不能将 Pi 的程序路径留在 Codex 下。程序位置与参数可在详情中查看；缺少对应配置显示未配置，不能只改标签。编辑对话框使用临时副本，点击应用才一次提交；取消后重新打开仍是原值。异步检查若晚于另一次 Agent 切换，不得覆盖当前结果。具体数据合同见 C5。

## 5. U03 同项目工作目录

同仓库多项启用后，目录策略默认“各自独立”，显示三件事：基线提交缩写、各项将使用的分支/目录、原目录未提交内容是否纳入（默认不纳入）。

```text
同项目工作目录
(●) 各自独立：每个 Agent 使用自己的目录和分支
( ) 使用已准备的目录
( ) 共用原目录：修改会直接相互可见，也可能互相覆盖

基线：当前已提交版本  a1b2c3d
1 Pi      demo-agent-1     分支 launcher/…/1
2 Codex   demo-agent-2     分支 launcher/…/2

原项目有未提交修改，新目录不会包含这些修改
[返回处理修改]  [使用已提交版本]
```

实际提交 ID 和路径来自 Git，不在产品中显示示例假值。只有脏工作区等影响结果的分支才要求选择；干净普通项目不增加重复确认。

使用已有目录时检查跨批次占用。冲突文案：`此工作目录正在由 {agent} 使用，无法作为另一个独立工作目录启动。` 提供“查看已有会话”“选择其他目录”“创建独立目录”。同一 worktree 的不同子目录仍按同一写入范围检查。已有会话处于独立模式时，新请求不能通过切换“共享”降低它的保护；需正常结束后重新配置。Unknown 显示“占用待核对”，不显示空闲。

目录策略在对话框中只修改副本；取消/Escape 不更新摘要。应用或恢复模板时，单选状态、摘要和草稿一次同步，下一份计划据此生成。结构缺字段或编辑版本冲突时保留原整体状态，不能应用一半；目录不存在、占用、资源不足等运行环境问题允许展示完整恢复后的配置并标错，但必须阻止启动。

各项可填写简短分工备注，默认不自动注入 CLI，以免依赖不同 Agent 的参数规则；提供“复制分工”。第一版也不宣称备注限定了 Agent 可改哪些文件。

启动后在“工作目录”详情中提供“打开文件夹”“复制分支”“打开主项目”。审阅帮助分四步：检查各目录修改 → 在各自目录提交需要保留的修改 → 在选定集成分支逐个合并 → 运行项目测试。显示当前基线分支，不假定仓库一定有 main。界面不替用户执行合并或删除。

## 6. U04 资源详情

主界面只放一行：`可启动 / 资源紧张 / 暂缓启动 / 检测不可用`，配合文字原因。数值由有效采样产生，并显示采样时间；不画持续刷新的图。

展开后：

- 当前可用物理内存、整机 CPU 压力、提交余量。
- 本次 Agent 数、已受管会话数、本次内存预算、系统保留余量。
- 受管负载的总 CPU 上限，包含 Git 准备与 Agent；明确只覆盖本应用托管的进程。
- 当前 Git 准备预算/阶段和目标盘可用空间；准备也需资源准入，不显示为没有成本的前置步骤。
- 内存硬限额说明：“超额分配可能使工具失败；工作目录会保留”。
- 一个“重新检查”按钮；它只重采样，不自动启动。

示例文案模板：`可用内存 {available}，保留余量后不足以启动 {count} 个 Agent。先减少本次启动项，或关闭其他应用后重新检查。`

内存不足时不提供默认“仍然强行启动”按钮，不引导清空工作集或结束不明进程。用户在其他软件释放资源后，连续恢复采样才解除阻塞，不按单次波动反复跳状态。

资源保护不是百分比动画。首版不暴露十几个阈值滑块；阈值在可审计配置中版本化，调整需重新验证。

## 7. U05 启动与恢复

提交后底部主按钮变为“正在准备”，冻结该启动计划；用户仍可移动窗口、查看状态。每项展示阶段：验证、准备目录、等待启动回执、已启动进程、失败、未确认。

| 情况 | 文案/动作 |
| --- | --- |
| 已提交但没有 Runner 回执 | “等待启动确认”，不显示 Agent 已就绪 |
| 10 秒未收到确认 | “结果未确认，终端可能已经启动。先查看终端。”；查看记录、重新检查 |
| 迟到请求尚未取得创建授权 | 提供“撤销未启动项”；撤销确认后显示“已撤销，旧请求不会执行” |
| 授权已领取/处于创建窗口 | 显示“正在核对，暂不能释放预算”；不提供会直接删记录的重置入口 |
| 明确启动前失败 | 显示具体原因，修复后只重试失败项 |
| 部分成功 | 成功项保留，不自动再次提交整组 |
| 资源预算未满足 | “已暂缓新增任务”，保留配置与已完成准备的目录 |
| 监控器异常退出 | “资源状态暂不可确认”，禁用新启动，提供恢复检查 |
| 上次应用异常退出 | 只恢复记录并核对，不自动重开所有 Agent |

“取消”停止未开始的准备和未领取的启动请求：通过监控器持久撤销授权后才释放预算。已经创建或状态未确认的项仍需核对；正在执行的 Git 写操作不强杀、不假装回滚。UI 区分“已撤销”和“仍在核对”，显示实际项数，不以一个“取消成功”覆盖全部状态。

全部成功确认后，若用户启用“启动后最小化”，才最小化；失败或未确认时保留状态页。“关闭配置窗口”说明轻量保护组件会跟随会话运行；“关闭终端”可能结束 Agent，两者分开表达。

退出码 0 仅表示进程正常退出，不表示代码任务成功。超过内存预算如有 OS 证据显示“达到内存上限”；普通进程异常退出只显示实际退出结果，不乱归因。

## 8. U06 组合与 U07 设置

组合保存名称、配置顺序、选中项、按 Agent 分开的程序/参数配置、布局偏好、目录策略及绑定规则。默认另存组合不覆盖现有组合；覆盖要明确显示名称。通用组合可不记目录，使用时继承新项目，但必须保留独立/共享策略；恢复时不能沿用当前界面的另一种策略。

“上次组合”的帮助文案固定为“最近一次切换模板前编辑的配置”。切走前保存人工编辑草稿；仅浏览其他模板不会覆盖这个快照。返回后必须恢复相同选中项、Agent/profile、布局和目录策略，例如仅启用第 4 项不能变成只启用第 1 项。没有快照时禁用并说明；“默认单个 Pi”是另一独立选项。

模板应用是整体事务，先构造并验证完整草稿再替换；模板缺字段时显示无法应用和修复入口，不部分恢复。所有控件与摘要从同一 Draft 渲染，禁止把目录模式只存于单选框或文字标签。详见 CONTRACTS C5。

自动保存的是最近草稿，不自动覆盖用户命名模板。拖入新项目或改 Agent 后显示“草稿已保存”；保存失败显示“尚未保存”，提供重试，不能无提示退出丢配置。

设置仅含主题（系统/浅/深）、文字缩放、启动后最小化、Terminal 位置、工作目录位置、最近项目管理、诊断入口。高对比度由系统优先覆盖。WPF 需显式处理系统文本比例或提供等效应用文字缩放，不假定它自动获得 WinUI 的文本缩放行为。没有常驻自动更新、云同步或账户系统。

诊断默认不含对话、完整参数和环境变量；导出前可预览。给出错误码、版本、阶段和可复制的说明；完整本地路径可按需脱敏。

## 9. 设计 token

以下数值采用 DIP 和原生资源，不依赖 Web 字体/CDN。用 ResourceDictionary 统一管理；高对比度映射系统颜色。

| 常用控件高度 | 最小 36；主启动按钮最小 40；文字缩放后可增高 |

## 10. 状态与视觉验收输入

必画/必实现状态：初次空态、一个配置、两个启用加两个停用、三格、四格、命令缺失、目录不可访问、脏 Git 项目、资源不足、等待回执、部分失败、未确认、配置损坏恢复、监控异常。

控件需覆盖 default / hover / pressed / focused / disabled / validation-error；禁用按钮旁边给出原因，不能要求用户猜。

原生原型阶段必须导出真实 WPF 截图、键盘操作记录、Narrator 检查结果及 DPI 矩阵。HTML/图片线框可以表达方向，但不能代替原生字体、输入法、拖拽和焦点验收。具体截图列表与判定标准见验收文档 V01～V09。

新增必验状态：Agent 切换后程序详情同步、模板恢复后独立/共享摘要同步、取消后重新打开仍是已应用值、已有目录占用、撤销确认/创建中无法撤销。对照 F14～F17 的实际计划断言，不能仅凭截图关闭问题。
