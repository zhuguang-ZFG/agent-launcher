# 实现架构与 UI 信息来源 v0.6

状态：已有四层技术预览实现。完整产品合同仍见 [CONTRACTS.md](CONTRACTS.md)；实际能力和验证结果由 [IMPLEMENTATION.md](IMPLEMENTATION.md) 记录，不能以架构图代替运行证据。

## 1. 边界与依赖

```text
App (WPF) ────────→ Core（配置、快照、准入规则）
   │                    ↑
   └─────────────→ Windows（计划存储、路径身份、Win32 Job）
   │                    ↑
   └─ 当前用户管道 → Worker monitor ← 当前用户管道 ─ Worker pane
                          │                            │
                     预算与目录占用                 CLI + 工具后代
                          └── 公共 CPU Job / 每项内存 Job ──┘
Windows Terminal 只承载 pane 终端；UI 不是 Agent 父进程的生命周期所有者。
```

不引入数据库服务、WebView、前端开发服务器或常驻 Agent 管理模型。Core 不引用 WPF；UI 不操作进程句柄；系统调用集中在 Windows 层。Worker 与 GUI 可独立退出。默认只启用一个配置。

| 工程 | 职责 | 禁止事项 |
| --- | --- | --- |
| AgentLauncher.Core | Draft、独立 profile、模板完整复制、LastEdited、预算计算、DTO | 不访问控件/磁盘/进程 |
| AgentLauncher.Windows | 原子文件、物理路径、系统采样、Job 创建与查询、命令解析 | 不把错误数值填零；不拼接 shell 输入 |
| AgentLauncher.Worker | 单实例监控器、请求仲裁、持久授权、Runner、恢复核对 | 不按超时重放；不释放未知占用 |
| AgentLauncher.App | 中文 WPF UI、拖入目录、编辑事务、检测/准备/提交/查看结果 | 不同步等待子进程；不把提交当就绪 |
| AgentLauncher.Tests | 纯模型回归与受限 Windows 集成验证 | 不调用用户真实项目的写操作、不耗尽桌面 |

当前 SDK 只有 8.0.419。技术验证先以 net8.0/net8.0-windows 构建；发布版迁移 .NET 10 LTS 的承诺保留，迁移后需重跑验证。此阶段产物标为技术预览，不冒充已达到 G4 发布门槛。

## 2. 并发、持久化与恢复

- GUI 一个 Dispatcher，事件调用异步服务；探测并发最多 2。只有 monitor 修改控制账本，同用户命名管道和单实例互斥锁防止重复配额组。
- Pipe 帧有大小/时间边界，操作和稳定请求 ID；技术预览按同构建配套运行，显式协议版本协商仍待补齐。处理串行，但长时间等待 CLI 不占用仲裁线程。
- 每个 attempt 的命名互斥锁包围核对授权、创建、写阶段和 Resume；恢复只尝试非阻塞获取。监控器持账本时不等待此锁。
- 创建前持久化意图，创建时关联公共 CPU Job 和内存 Job，禁止先创建再关联的回退。失败不得恢复未受保护进程。
- Pending 撤销落盘后才能释放预算；Creating、ResumeIntent、Unknown 保留占用。仅 Job 成员归零且尝试已终结才释放。单项失败不撤销其他已运行项。
- 配置、账本写临时文件并 flush，再原子替换，保留上份备份；同文件读写由跨进程互斥串行，避免 Windows 替换期间瞬时误读。损坏/未来 schema 阻止覆盖和新启动。记录参数用于实际执行，但常规错误日志不打印参数。
- 无 kill-on-close、无自动 worktree 清理、无自动合并。监控器重启先核对记录；原有任务正常存活并不意味着新提交可以绕过核对。

## 3. UI 信息合同

第一屏回答四个问题：在哪里运行、运行哪个程序、多少个会话、现在能否启动。

| 区域 | 展示内容 | 数据来源 | 缺失/失败显示 |
| --- | --- | --- | --- |
| 项目 | 完整路径；可编辑/浏览/拖入 | Draft.defaultProject | 未选择 / 不存在，不显示示例路径 |
| 配置行 | 启用、位置、Agent、实际程序、目录覆盖 | slot + 当前 Agent profile + 检测结果 | 未找到命令 / 适配未验证 |
| 参数详情 | 程序路径、逐行参数、工作目录、任务备注 | EditSession 副本 | 应用失败保留编辑；取消不改草稿 |
| 目录策略 | 独立创建 / 已准备目录 / 明确共享；准备后的路径与基线 | Draft + Git 核对结果 | 占用待核对、准备失败保留目录 |
| 布局 | 仅启用项、稳定配置编号 | orderedSlots | 0 项显示先选择，不生成空窗格 |
| 资源行 | 可用内存、系统保留、本次预算、采样时间 | Win32 采样 + monitor 账本 | 检测不可用，不显示通过 |
| 资源详情 | 总 CPU 35%、每项内存 2 GiB、占用预算、提交余量 | 策略 + 有效采样 | 明确限制范围和采样过期 |
| 启动结果 | 逐项阶段、工作目录、错误/退出码、时间 | 持久计划 + 回执 + monitor 核对 | 等待确认 / 未确认，不写就绪或任务完成 |
| 保存状态 | 已保存 / 尚未保存及原因 | 原子写入结果 | 不用 toast 掩盖失败，不覆盖旧配置 |

UI 不显示伪造 CPU/内存数字、假登录状态、假“已就绪”。颜色只辅助文字；路径可复制；关键错误保持可见。一般错误不弹堆栈。窗口使用系统标题栏，可键盘操作；小工作区滚动内容，操作栏保持可达。

## 4. 实施顺序与门禁

1. 修复 HTML 的真实配置状态问题，纯模型断言覆盖程序路径/参数、目录策略、深拷贝、取消和 LastEdited。
2. G1：受限进程的创建时 Job 关联、总 CPU/内存设置、迟到授权撤销、崩溃边界、空闲开销；先用临时目录和短生命周期程序。
3. G2/G3：WPF 绑定统一 Draft，逐项显示真实检测和回执；目录、模板与启动链路验证。
4. 留存实际构建、测试和 UI 截图。真实 Agent 的版本探测不等于交互兼容性；桌面短测不等于压力验收。
