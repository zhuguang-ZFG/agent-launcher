# vibe coding 扩展实施计划

日期：2026-11-11。状态更新：2026-11-12，S0.1–S0.5 / S1–S4 已有实现与验证记录；S0.6、S5 未完成，不能将整份计划标为完成。对应 [功能规格](../specs/2026-11-11-vibe-workbench-spec.md)。本计划不代表 Omp 历史崩溃已经全部归因。

## 1. 交付原则

每阶段独立提交、验证、推送并核对对应 SHA 的 CI。持续保留当前通用 CLI 启动路径；实验适配不可成为基础启动依赖。生产构建与测试构建顺序执行，避免共享 bin/obj 和条件编译产物相互干扰。

阶段依赖：

```text
S0 稳定性封板
 └─ S1 参数预设与能力检测
     └─ S2 任务卡、整任务队列与续跑（首个扩展版本）
         ├─ S3 共享资源池内核原型 → 产品化
         └─ S4 改动审查、验证结果、GitHub CI
             S2 + S3 + Omp 能力实验 → S5 Omp 多会话宿主
```

S3 与 S4 在依赖满足后可独立安排；本计划不要求启动多个开发 Agent。

退出条件：VC-G01/G02 与现有 gate 通过；代码和发布产物版本明确；待观察项清楚列出。现有退出机制未闭环时，不用新增功能掩盖失败。

## 3. S1：参数预设与能力检测

### 交付切片

1. **S1.1 数据合同**：AgentCapability 与命名参数预设，字段限长、独立复制、版本缓存失效。先不改启动 argv 协议。
2. **S1.2 参数界面**：在现有详情编辑器增加预设入口、逐参数预览和未知能力提示；不提供拼接任意 shell 的“高级模式”。
3. **S1.3 版本适配**：先 Omp 与 Codex，各验证一个安装版本的帮助和退出行为。模型/恢复等预设逐条记录可执行证据，其他 Agent 保留通用参数列表。
4. **S1.4 验收**：短长参数、等号形式、`--`、空字符串、中文/空格/换行、分号和末尾反斜杠通过真实子进程回显；升级失效、探测超时和错误参数有明确反馈。

涉及：Core 新 `AgentCapabilities`/预设模型；Windows 新受控探测服务；现有 `Commands` 适配；App 详情编辑器；native 与 WPF 测试。

验收：VC-A01/A02；截图覆盖 150% 文本和窄窗。回退：禁用预设面板后仍可使用原参数列表；不改用户原 profile。

## 4. S2：任务卡、整任务队列与安全续跑

### 交付切片

1. **S2.1 任务持久化**：独立版本任务文件、修订号、备份、用户验收项；生成有界可复制任务说明。先手工创建，不添加模型调用。
2. **S2.2 尝试关联**：TaskRun 与 Attempt 一对一关联，任务完成和进程结束分离；历史按任务聚合。
3. **S2.3 调度状态机**：Core 纯队列策略，Worker 单消费者；排队不创建进程，准备阶段仍走现有 Git/资源准入。执行授权固定任务修订；重启恢复不擅自重放。
4. **S2.4 UI**：任务列表显示等待原因、运行状态、检查状态和下一步；默认并发 1，用户可调小范围并发但仍受硬保护。保留当前快速启动页。
5. **S2.5 续跑**：Omp 首先验证指定 SessionRef 的能力与租约；其他 CLI 按能力表逐步增加。无恢复能力则明确新开，不模仿恢复。
6. **S2.6 故障验收**：领取前后崩溃、重复请求、App 关闭、目录被替换、会话已占用、取消排队与活动后代、任务依赖失败。

涉及：Core `Tasks`/`QueuePolicy`；Windows `TaskStore`/能力适配；Worker 队列消费与协议版本；App 任务页；隔离 integration 测试。

验收：VC-Q01/Q02/R01 全过；同一授权快照从未执行两次；100 个队列项不会生成 100 个空闲进程。首个扩展版本在此结束，可以实际交付使用。

## 5. S3：共享资源池

### 第一关：内核可行性原型

在隔离夹具实现 CPU 根、池、单项三个 Job。验证挂起创建时原子关联、继承后代归属、两个项借用池额度、单项与池限制分别触发、根 CPU 配置不变。测试分配使用小额度，不在用户主机做数 GiB 压力冲击。

增加 monitor 崩溃、句柄丢失、父退出子存活、池下未归属进程、同名对象已存在等场景。若归属或恢复无法可靠证明，停止产品化并保留独立模式；记录原型失败不减少测试门槛。

### 第二关：合同与产品化

1. **S3.1 记账**：PoolId 与冻结策略、按池一次计费、按项累计规划、Git 独立计费；加入计划摘要和授权签名。
2. **S3.2 生命周期**：Worker 持有池与单项句柄；恢复先证明全部成员；未知成员不释放；池结束需要所有项与后代证明。
3. **S3.3 迁移**：配置/协议/ledger 版本化；旧记录读作独立模式，旧 Worker 必须拒绝不认识的池语义。只有新批次可加入新池。
4. **S3.4 交互**：设置里明确选择独立/共享；展示池和单项两层额度、当前/峰值/未知；支持从排队项移除，但不迁移运行项。
5. **S3.5 对照**：相同双任务负载测独立与共享模式的分配拒绝、峰值、耗时和系统余量。只声明额度利用结果，不宣称进程复用节省内存。

验收：VC-P01/P02；原有 2 层 Job 场景全部通过；压力时只停止接纳新任务，未授权终止数为零。回退：禁止创建新池，已启动池由原 Worker 完成生命周期，不能用旧版本强行接管。

## 6. S4：审查、验证与 CI

1. **S4.1 Diff**：明确基准、受管 worktree、有限输出、未跟踪选择、大文件和二进制摘要；只读第一版。
2. **S4.2 检查配置**：可复用命名命令，首次使用由用户选择；执行仍受资源管理，有超时/取消和有界日志。
3. **S4.3 结果绑定**：SHA 加工作区指纹，任何相关修改使结果过期；不同任务结果不混用。
4. **S4.4 提交预览**：显式选文件，执行前重核索引与文件状态；冲突/HEAD 改变时停止，不自动覆盖。
5. **S4.5 GitHub**：先只读精确 SHA 的 checks/workflows，再加用户点击的推送/PR 操作；失败、无权限、缺少 workflow、网络断开均有独立状态。
6. **S4.6 本机预览**：列出受管开发端口并用默认浏览器打开；不嵌入新浏览器引擎。

验收：VC-D01/C01；模拟延迟 CI 和旧提交成功不误报新提交绿色；Agent 同时改文件不会把未审阅内容提交。回退：所有写入入口可关闭，保留 Git 原生流程。

## 7. S5：Omp 多会话宿主实验

只在 S0、S2、S3 完成且 Omp 版本能力经过实际测试后进入。

1. **S5.1 隔离审计**：核验 SDK、AgentRegistry、SessionManager、扩展全局状态、环境/cwd、取消与权限。写能力表，未知项直接阻塞“支持”标记。
2. **S5.2 最小宿主**：一个可选外部宿主两个会话，独立 worktree 与事件通道；先禁用未验证扩展。基础 CLI 模式不依赖宿主。
3. **S5.3 工具队列**：只调度明确的 host-tool 调用，加入取消与队列确认；未覆盖工具清楚显示，不宣称全部工具受控。
4. **S5.4 故障演练**：原生崩溃、宿主断管、消息背压、取消一个会话、会话文件损坏与租约占用；从不自动重放最后 prompt。
5. **S5.5 量化对照**：独立双 CLI vs 同宿主双会话，在相同插件与代表性任务下至少五轮、每轮十分钟；记录基线/稳态/峰值、延迟与完成情况。内存中位数改善目标 20%，隔离通过率必须 100%。数字是验收目标，不是预期保证。
6. **S5.6 可选 MCP 复用**：逐服务做多客户端隔离验证；首期允许支持名单，其余每会话独立启动。

验收：VC-O01/O02 与所有已声明覆盖的工具协议测试；任一串会话错误即不发布。失败时保留通用 CLI 模式，不把共享宿主设为默认。

## 8. 统一验证与发布

- 纯策略测试验证状态与预算边界；原生夹具验证真实 Job/argv；集成测试验证跨进程恢复；WPF 检查验证可见反馈与键盘；原型/浏览器检查保持现有门禁。
- 使用 `scripts/test.ps1` 完整 gate；局部测试仅作开发定位，不能替代发布门禁。
- 所有测试使用隔离临时根，禁用真实模型请求；真实 Agent 冒烟另列版本和授权范围。
- 不同时运行生产 publish 与 `INTEGRATION_TESTS` publish。正式产物验证无测试根、模拟采样或故障注入标记。
- 每阶段记录：源提交、测试输入变化、通过/失败/受阻、CI run/目标 SHA、产物路径和回退方式。
- CPU/物理/提交硬保护、fail-closed、原子持久化和精确参数合同始终保留；任何改变须先修订明确的合同及故障用例。

## 9. 实施前仍需实验解决的事项

| 问题 | 如何解决 | 是否阻塞首个扩展版本 |
| --- | --- | --- |
| Omp 历史两次崩溃是否都因限额 | 新退出证据、原生日志、代表性负载；不靠退出码猜测 | 阻塞稳定性结论，P1 规划可继续 |
| 三层 Job 原子关联与恢复 | S3 原生原型与注入测试 | 不阻塞参数/任务队列 |
| 通用 CLI 内部工具能否排队 | 不假定能；首期只整任务调度 | 不阻塞 |
| Omp 多会话扩展隔离及实际内存收益 | 固定版本 SDK 原型与五轮对照 | 只阻塞 P3 宿主 |
| MCP 哪些服务可安全共享 | 逐服务协议与隔离测试 | 不阻塞独立模式 |

推荐实现入口：稳定性封板 → 参数预设 → 任务卡与队列 → 手工安全续跑。之后按资源痛点优先共享池，再扩大审查和验证体验。
