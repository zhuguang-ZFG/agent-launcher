# 远程执行规格

版本：2026-11-18 对齐，同日记三台同权 · 对应产品 SPEC v0.6.1 · 依据 `main` `6daa7de` 与 IMPLEMENTATION §83–§84；同权决定见 IMPLEMENTATION §88

权威关系：产品范围以 [SPEC.md](../../SPEC.md) 3.4 为准；可执行合同以 [CONTRACTS.md](../../CONTRACTS.md) C14 为准；验收以 [ACCEPTANCE.md](../../ACCEPTANCE.md) R23～R29 为准。本文件说明目标、边界和已实现与仍未承诺的行为，不取代合同条文。本次对齐与同权记录不重跑门禁，不新增通过数。

## 1. 为什么纳入范围

v0.6 的 SPEC 3.3 曾把「远端/WSL」列为暂不实现。`main` `6daa7de` 已经可以登记 Linux SSH 主机、按槽位启动远程 Agent、把远程批次从本地 Job 和本地内存/CPU 准入中分开，并用 fake-ssh 验证存活、退出和断连。继续把远端写在「暂不实现」里会造成规格与代码冲突。

本规格把 SSH 远程 Linux 主机正式纳入范围，并写清已实现合同与仍然开放的边界。WSL、远程 Windows 主机和远程桌面仍不在范围。

## 2. 目标与非目标

### 2.1 目标

- 开发者把单个槽位指向已登记的 Linux SSH 主机，在指定远程目录启动受支持的 CLI Agent。
- 本地配置窗口负责主机与槽位登记、启动预约、状态展示和回执；Windows Terminal 继续承载输入输出。
- 远程进程的 CPU 和内存由远程主机负责。本地监视器仍核对共享安全闸门（账本、授权、程序身份），但不为远程条目创建本地 Job 或 custody，也不按本地内存或 CPU 压力拦截纯远程批次。
- 8 个窗格名额包含每一个非终态 Agent，不论本机还是远程（Worker reserve/begin，以及界面 `ActiveAgentCount` / `UpdateLaunch`，`MaxConcurrentAgents = 8`）。把槽位放到 VPS 不腾出本地窗格名额。尚未操作员释放的 `Disconnected` 继续占一个名额。见 CONTRACTS C14。
- 同一批次可以同时包含本地槽位和远程槽位：远程条目跳过本地内存/CPU 准入，本地条目仍按原模式接受或拒绝。8 窗格名额仍然把该远程条目算进去。同权不把远端主机的内存与 CPU 限额变成与本机相同。
- 三台同权（2026-11-18 产品决定）：本机、京云、阿里云对共享项目工作区同权。任一台上的 agent 都可以修改该工作区，另外两台必须看到同一批文件。同权要求双向工作区同步，推荐 Mutagen。操作员确认的断线重新挂接是维持同权所要求的行为，已实现（R33，§89）。细节见第 5、6 节。自动重连仍未实现。

### 2.2 非目标

- WSL、远程 Windows、远程桌面、在远程主机上安装或登录 Agent。
- 在配置、日志或回执中保存 SSH 密码或私钥内容。配置只保存可选的私钥路径。
- 远程 cgroup 或 `MemoryLimitBytes`。该字段目前必须拒绝，界面不得宣称已限制远程内存。启动命令中的 `NODE_OPTIONS=--max-old-space-size=1024` 只限制 Node 老生代堆，非 Node 进程忽略它；它不关闭本条。
- 自动证明远程进程已退出、自动重连，或把 SSH 断开当作可以释放预算的终态。`Disconnected` 只有操作员确认释放（R28）或既有 boot 证明才能终态化。操作员确认的重新挂接（R33）不终态化，也不在本条里：它是维持三台同权的已实现路径，见第 5、6 节。
- 结束本地 SSH 客户端就等于远程 Agent 已退出。强制分配伪终端后，断开会话通常会带走前台进程，但不能作为证明，也不能作为释放预算的依据。
- 把远程批次纳入本地 Job 限额或本地共享池。8 窗格并发名额包含远程条目，见 2.1。

## 3. 形态与配置

配置对象 `RemoteHosts` 保存远程主机，字段为稳定 `Id`、显示名称、地址、SSH 端口、SSH 登录用户、Agent 运行用户、可用 Agent 类型、可选私钥路径，以及默认工作区同步模式。名称和地址各自唯一（大小写不敏感）。槽位以 `RemoteHostId` 引用主机，因此重命名不会孤立槽位；删除主机前必须先核对应槽位引用。

槽位可选填写 `RemoteHostId` 和 `RemoteDirectory`。主机留空表示本地执行。远程目录必须是绝对路径或 `~/` 开头。远程工作目录可由本地项目路径推导（默认拼到 `~/work/<项目名>`），但启动时以槽位保存的远程目录为准。

启动使用本机 `ssh` 客户端，参数以参数列表传递，而不是拼成一层 shell 字符串：强制分配伪终端（`-tt`）、`BatchMode=yes`、连接超时 10 秒，登录后执行 `su - <AgentUser> -c …`，在远程工作目录启动 Agent。远程命令注入固定 `export NODE_OPTIONS=--max-old-space-size=1024;`，只作用于 Node。当前支持的远程 Agent 类型为 `pi`、`kimi`、`qodercli`、`omp`、`codex`；未知类型或 `custom` 必须拒绝。认证只走 `ssh-agent` 或 `SshKeyPath`；`BatchMode=yes` 下不会弹出密码框。本规格不承诺交互式密码登录。

界面（UX14，IMPLEMENTATION §84）：每个槽位的 Agent 选择都包含已登记主机的云候选。选中云候选即绑定 `RemoteHostId`；远程目录为空时按 `~/work/<项目名>` 派生。选本机候选即解除绑定并清空远程目录。

本机维护（§83）：主机卡片可测试免密连接、检查版本，并在显示确切命令且二次确认后升级远端 Agent。升级命令有默认映射，主机编辑可以按 agent 覆盖。桌面快捷方式启动时，ssh 工具优先使用由 `git.exe` 推导出的 Git `usr/bin`，以避免解析到禁用的 Windows 服务版 `ssh-agent`（错误 1058，R31，§84）。

## 4. 执行域与校验

远程计划只受远程合同约束：准备和预约阶段不重建本地资源策略、不创建本地 Job 或 custody、不因本机内存或 CPU 压力拒绝纯远程批次。同一监视器上的本地计划仍按原准入规则处理。账本写入、授权代次和程序身份等共享安全闸门对两域同样生效。本地预算为 0 时，豁免不得扩散到本应拒绝的本地计划。8 窗格名额把远程条目算进去，见 2.1。

远程参数若混入 Windows 盘符或 UNC 路径（包括 `--add-dir=D:\…` 这种形式）必须拒绝，并提示「远程参数包含 Windows 本地路径」。合法远程路径和 `http://` URL 不受影响。

## 5. 生命周期

以本地 SSH 客户端进程的存活和退出码作为监视器能直接证明的事实，同时必须向操作员说明其局限。

| 事实 | 状态 | 预算 |
| --- | --- | --- |
| SSH 进程仍在，且能用 PID 与创建时间排除复用 | `Started` | 继续占用 8 个窗格名额之一（远程条目不占本地 Job，账本条目保持非终止） |
| SSH 正常退出（退出码不是 255） | `Settled` | 可以释放 |
| SSH 退出码 255（连接断开或认证/网络失败） | `Disconnected` | 不释放，继续占一个窗格名额，直到操作员确认释放。说明「远程进程可能仍存活，请手动核对远程主机状态」 |
| 在 `SpawnIntent` / `CreatedSuspended` / `ResumeIntent` 等 Started 之前的阶段崩溃或取消 | `Disconnected` | 不释放，继续占一个窗格名额。说明「远程创建中断（远程进程可能仍存活）」 |
| 系统重启后，记录的进程时间早于本次启动时间 | 可按既有 boot 分支释放陈旧 `Disconnected` | 仅在能证明这是重启前的本地 SSH 记录时适用 |

`Disconnected` 在操作员完成核对并显式确认释放之前，必须保持非终止，并继续占用 8 个窗格名额中的一个。已实现的入口是「核对并确认释放」（R28，§83）：记录主机、远程目录、判断（仍在 / 已不在 / 无法判断）和释放原因；只有判断为已不在并二次确认才调用 `release-remote`，写入 `operator-release.json` 并终态化。仍在或无法判断不改变账本。界面不提供会盲目重启同一远程条目的一键重试。为维持三台同权，旁边另有「核对并确认重新挂接」（R33，§89）：未确认不动作；确认后远程进程仍在才恢复同一条账本上的本地 SSH，并在原来启用了 Mutagen 或 SSHFS 时重新建立同步；`None` 不写成已同步，也不是同权；进程已不在则拒绝且不自动释放。本地挂接结束回到 `Disconnected`，不释放名额。确认释放不代替重新挂接。不会自动重连。fake-ssh 回归不打开真实 VPS。

结束或回收本地 SSH 客户端，不能单独把条目改为 `Settled`。确认释放只结束本地账本占用，不承诺结束远程主机上的进程。

## 6. 工作区同步

2026-11-18 产品决定「三台同权」。对等机器是操作者的本机 Windows（本机）、京东云 VPS（文档称京云）、阿里云 VPS（文档称阿里云）。文档不写真实主机名、地址、用户名或密钥。同权是工作区对等：任一台上的 agent 都可以修改共享的项目工作区，另外两台必须看到同一批文件。京云与阿里云上的 agent 仍在各自的远端机器上运行。同权的实现方式是必须的双向工作区同步。远端进程没有本机文件系统的直接访问权，也不能不经同步就改本机上的任意文件。

同权模式要求双向同步。推荐机制是 Mutagen。`SshfsMount` 是本规格已经允许的 SSHFS 挂载备选。不新增其他同步后端，也不把 SSHFS 新写成三台之间的同步机制。`None` 下各机只看见自己的目录，表现得像互相断开，因此不是同权。

已实现的启动路径仍把同步当作可选：可以选择 `None`、`Mutagen` 或 `SshfsMount`。选择 `None` 时，远程 Agent 只能使用远程目录里已有的文件，这次启动不是同权。当前实现不因这项决定拒绝 `None`；本文不把「拒绝 `None`」写成已实现。§83–§84 已记录的 Mutagen 双向活测仍只覆盖当时的单对路径，不改写成三台同权已活测。

模式为：

- `None`：不同步。远程 Agent 只能使用远程目录里已有的文件。这种模式不是同权。
- `Mutagen`：推荐的持续双向同步。以 Agent 运行用户连接，使远程新建文件归属该用户。启动前等待就绪，超时 2 分钟。结束时先 `flush`，失败或超时必须保留会话并写入回执，不得假装已经收敛后直接 `terminate`。会话名写入 `attempts/<id>/sync-session.json`。同步徽章按该名字匹配终态回执，供配置窗口重启后继续显示（§84）。§83 里「会话名未持久化」是该修正之前的记录。
- `SshfsMount`：既有备选。依赖 WinFsp 与 SSHFS-Win，挂载点自动选择空闲盘符。

若启用同步，同步用的远程路径必须与启动用的远程工作目录一致，本地路径必须是完全限定路径。删除远程多余文件是危险操作，必须显式选择，默认不得带 `--delete`。辅助 rsync 参数构造不是启动主路径；若使用，密钥路径不得未加引号地拼进 `-e` 命令字符串。

Windows OpenSSH 与 Mutagen 组合存在已知阻塞风险，文档应建议使用 Git for Windows 提供的 OpenSSH，但不把某一发行版写成唯一支持承诺。

## 7. 安全

- 配置、启动记录和普通日志不得写入密码、口令或私钥内容。私钥只以本机路径引用，且该路径不应指向仓库内文件。
- 自动交付或远程命令说明里，必须继续提示不要把密钥写进参数。
- 主机地址、用户名可以保存在配置中；真实验收记录不得把私钥、密码或可登录的完整命令写进将要提交的文档。
- 本规格不引入启动器代管的远程提权清理，也不在远程主机上自动修改与 Agent 无关的系统配置。

## 8. 已实现与仍开放

已有实现与已记录证据（以 IMPLEMENTATION §82–§84 原文为准。本次文档对齐不重跑、不改写那些计数）：

- 主机编辑校验、槽位引用、远程规格校验，以及 Windows 本地路径拒绝（R27）。
- 分域准入（R26）：纯远程批次在本地内存/CPU 压力下仍可预约/开始；本地计划仍被拒绝。8 窗格名额仍然包含该远程条目。
- fake-ssh 集成：存活保持 `Started`、正常退出转为 `Settled`、255 转为 `Disconnected`、Started 前中断转为 `Disconnected`（R23～R25）。
- 操作员确认释放（R28，§83）：`release-remote` 与「核对并确认释放」。非 Gone、缺原因、未确认、本地 SSH 仍存活或尝试锁未释放时账本不变。回归使用 fake-ssh。
- 免密远程维护、方案 C 界面、只读查看改动、同步徽章、远端只读资源（§83）。同步会话名持久化补上了 §83 当时「未持久化」的限制（§84）。
- R30 同步探针在孙进程持有管道时按时返回；R31 桌面启动优先使用 Git 自带 ssh 工具，避免 ssh-agent 1058；UX14 全槽位云选择器；Node 专用固定堆上限（§84）。
- R29：opt-in 活测入口 `RemoteLiveChecks` 不进入 CI。§83–§84 已记录双 VPS 活测和发货预览包复验，文档只引用证据路径。这不是浸泡，也不是远端 CI。
- §84 记录的最近一次完整门禁：`scripts/test.ps1` 退出 0；该节对隔离 `--ui-check` 写出 397/397（含 UX14），没有另写完整门禁的 UI 条数。本文不补这个数字。

仍开放：

- `MemoryLimitBytes` 与远程 cgroup。Node 堆参数不关闭此项。
- SSH 断开后的自动重连。操作员确认的重新挂接（R33）已有 fake-ssh 回归，用来维持三台同权；它不代替 R28，也不新开真实 VPS 活测。`Disconnected` 仍只有操作员确认释放或既有 boot 证明才能终态化。
- G4、ACCEPTANCE §11 浸泡、独立人类可用性、远端 CI。
- 含远程 UI 的后续改动仍须跑完整 `scripts/test.ps1`。只用 `-SkipUi -SkipBrowser` 不能关闭 C14。

## 9. 已知限制

- 把工作放到 VPS 不腾出 8 个窗格名额。未释放的 `Disconnected` 继续占一个名额。同权不把远端主机纳入本地内存/CPU 准入。
- 同步模式 `None` 不是三台同权。当前实现仍允许选择 `None`。操作员确认的重新挂接已实现（R33）；选择 `None` 的挂接不会把工作区写成已同步。
- 监视器只能直接证明本地 SSH 客户端的存活，不能在未登录远程主机的情况下枚举远程进程。
- 会话扫描、Qoder 多目录归属等本地限制对远程会话同样适用时，不得宣称更强的自动归属。
- 同标题终端召回可能选错窗口。句柄全部丢失的旧池仍须重启后再核对。工作集回收不证明 commit 下降。
- 配置窗口完全退出后不补播会话通知；托盘后台可以继续。
- 远程执行保持技术预览。R28/R29 的已记录证据不写入稳定发布说明，也不关闭 G4。
