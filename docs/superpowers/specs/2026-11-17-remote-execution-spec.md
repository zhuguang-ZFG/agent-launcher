# 远程执行规格

版本：2026-11-17 · 对应产品 SPEC v0.6.1  
权威关系：产品范围以 [SPEC.md](../../SPEC.md) 3.4 为准；可执行合同以 [CONTRACTS.md](../../CONTRACTS.md) C14 为准；验收以 [ACCEPTANCE.md](../../ACCEPTANCE.md) R23～R29 为准。本文件说明目标、边界和已实现与待补齐的行为，不取代合同条文。

## 1. 为什么纳入范围

v0.6 的 SPEC 3.3 曾把「远端/WSL」列为暂不实现。当前未提交代码已经可以登记 Linux SSH 主机、按槽位启动远程 Agent、把远程批次从本地准入和 Job 中分开，并用 fake-ssh 验证存活、退出和断连。继续把远端写在「暂不实现」里会造成规格与代码冲突。

本规格把 SSH 远程 Linux 主机正式纳入范围，并写清已实现合同与必须补齐的缺口。WSL、远程 Windows 主机和远程桌面仍不在范围。

## 2. 目标与非目标

### 2.1 目标

- 开发者把单个槽位指向已登记的 Linux SSH 主机，在指定远程目录启动受支持的 CLI Agent。
- 本地配置窗口负责主机与槽位登记、启动预约、状态展示和回执；Windows Terminal 继续承载输入输出。
- 远程进程的 CPU 和内存由远程主机负责。本地监视器仍核对共享安全闸门（账本、授权、程序身份），但不为远程条目创建本地 Job 或 custody，也不把远程条目计入本地 8 窗格并发预算。
- 同一批次可以同时包含本地槽位和远程槽位：远程条目跳过本地准入，本地条目仍按原模式接受或拒绝。

### 2.2 非目标

- WSL、远程 Windows、远程桌面、在远程主机上安装或登录 Agent。
- 在配置、日志或回执中保存 SSH 密码或私钥内容。配置只保存可选的私钥路径。
- 远程 cgroup 或内存上限。`MemoryLimitBytes` 目前必须拒绝，界面不得宣称已限制远程内存。
- 自动证明远程进程已退出、自动重连、或把 SSH 断开当作可以释放预算的终态。
- 结束本地 SSH 客户端就等于远程 Agent 已退出。强制分配伪终端后，断开会话通常会带走前台进程，但不能作为证明，也不能作为释放预算的依据。
- 把远程批次纳入本地 Job 限额、本地共享池或 8 窗格并发池。

## 3. 形态与配置

配置对象 `RemoteHosts` 保存远程主机，字段为稳定 `Id`、显示名称、地址、SSH 端口、SSH 登录用户、Agent 运行用户、可用 Agent 类型、可选私钥路径，以及默认工作区同步模式。名称和地址各自唯一（大小写不敏感）。槽位以 `RemoteHostId` 引用主机，因此重命名不会孤立槽位；删除主机前必须先核对应槽位引用。

槽位可选填写 `RemoteHostId` 和 `RemoteDirectory`。主机留空表示本地执行。远程目录必须是绝对路径或 `~/` 开头。远程工作目录可由本地项目路径推导（默认拼到 `~/work/<项目名>`），但启动时以槽位保存的远程目录为准。

启动使用本机 `ssh` 客户端，参数以参数列表传递，而不是拼成一层 shell 字符串：强制分配伪终端（`-tt`）、`BatchMode=yes`、连接超时 10 秒，登录后执行 `su - <AgentUser> -c …`，在远程工作目录启动 Agent。当前支持的远程 Agent 类型为 `pi`、`kimi`、`qodercli`、`omp`、`codex`；未知类型或 `custom` 必须拒绝。认证只走 `ssh-agent` 或 `SshKeyPath`；`BatchMode=yes` 下不会弹出密码框，因此「默认可用密码登录」不是本规格的承诺。

## 4. 执行域与校验

远程计划只受远程合同约束：准备和预约阶段不重建本地资源策略、不创建本地 Job 或 custody、不因本机内存或 CPU 压力拒绝纯远程批次。同一监视器上的本地计划仍按原准入规则处理。账本写入、授权代次和程序身份等共享安全闸门对两域同样生效。本地预算为 0 时，豁免不得扩散到本应拒绝的本地计划。

远程参数若混入 Windows 盘符或 UNC 路径（包括 `--add-dir=D:\…` 这种形式）必须拒绝，并提示「远程参数包含 Windows 本地路径」。合法远程路径和 `http://` URL 不受影响。

## 5. 生命周期

以本地 SSH 客户端进程的存活和退出码作为监视器能直接证明的事实，同时必须向操作员说明其局限。

| 事实 | 状态 | 预算 |
| --- | --- | --- |
| SSH 进程仍在，且能用 PID 与创建时间排除复用 | `Started` | 继续占用（远程条目不占本地 Job，但账本条目保持非终止） |
| SSH 正常退出（退出码不是 255） | `Settled` | 可以释放 |
| SSH 退出码 255（连接断开或认证/网络失败） | `Disconnected` | 不释放。说明「远程进程可能仍存活，请手动核对远程主机状态」 |
| 在 `SpawnIntent` / `CreatedSuspended` / `ResumeIntent` 等 Started 之前的阶段崩溃或取消 | `Disconnected` | 不释放。说明「远程创建中断（远程进程可能仍存活）」 |
| 系统重启后，记录的进程时间早于本次启动时间 | 可按既有 boot 分支释放陈旧 `Disconnected` | 仅在能证明这是重启前的本地 SSH 记录时适用 |

`Disconnected` 在操作员完成核对并显式确认释放之前，必须保持非终止。当前实现只提供说明对话框，还没有把「已核对远程主机」写成可审计的释放操作；这是必须补齐的缺口，验收见 R28。在该操作落地前，不得在界面提供会盲目重启同一远程条目、从而可能造成重复进程的一键重试。

结束或回收本地 SSH 客户端，不能单独把条目改为 `Settled`。

## 6. 工作区同步

同步是可选能力，不是远程启动的前提。模式为：

- `None`：不同步。远程 Agent 只能使用远程目录里已有的文件。
- `Mutagen`：推荐的持续同步。以 Agent 运行用户连接，使远程新建文件归属该用户。启动前等待就绪，超时 2 分钟。结束时先 `flush`，失败或超时必须保留会话并写入回执，不得假装已经收敛后直接 `terminate`。
- `SshfsMount`：备选。依赖 WinFsp 与 SSHFS-Win，挂载点自动选择空闲盘符。

若启用同步，同步用的远程路径必须与启动用的远程工作目录一致，本地路径必须是完全限定路径。删除远程多余文件是危险操作，必须显式选择，默认不得带 `--delete`。辅助 rsync 参数构造不是启动主路径；若使用，密钥路径不得未加引号地拼进 `-e` 命令字符串。

Windows OpenSSH 与 Mutagen 组合存在已知阻塞风险，文档应建议使用 Git for Windows 提供的 OpenSSH，但不把某一发行版写成唯一支持承诺。

## 7. 安全

- 配置、启动记录和普通日志不得写入密码、口令或私钥内容。私钥只以本机路径引用，且该路径不应指向仓库内文件。
- 自动交付或远程命令说明里，必须继续提示不要把密钥写进参数。
- 主机地址、用户名可以保存在配置中；真实验收记录不得把私钥、密码或可登录的完整命令写进将要提交的文档。
- 本规格不引入启动器代管的远程提权清理，也不在远程主机上自动修改与 Agent 无关的系统配置。

## 8. 已实现与待补齐

已有实现与测试（以 IMPLEMENTATION §82 及对应测试为准，不把它们等同于本规格全部关闭）：

- 主机编辑校验、槽位引用、远程规格校验，以及 Windows 本地路径拒绝（R27）。
- 分域准入（R26）：纯远程批次在本地压力下仍可预约/开始；本地计划仍被拒绝。
- fake-ssh 集成：存活保持 `Started`、正常退出转为 `Settled`、255 转为 `Disconnected`、Started 前中断转为 `Disconnected`（R23～R25）。
- 工作区同步的集成测试夹具；opt-in 的真实 VPS 活测入口 `RemoteLiveChecks`（不进入 CI）。

待补齐：

- 操作员确认释放（R28）。当前「手动核对状态」只弹出说明，不写回执、不改变账本。
- 真实 VPS 活测证据（R29）。尚未执行；执行时使用隔离测试根目录、真实 ssh（不得被测试用假 `ssh.exe` 遮蔽），证据归档在忽略目录，文档只引用证据路径。
- 在含 UI 和浏览器的完整 `scripts/test.ps1` 门禁中回归远程相关 UI，而不是只跑 `-SkipUi -SkipBrowser`。
- 远程内存上限仍明确不实现，直到另有规格和远程侧证据。

## 9. 已知限制

- 监视器只能直接证明本地 SSH 客户端的存活，不能在未登录远程主机的情况下枚举远程进程。
- 会话扫描、Qoder 多目录归属等本地限制对远程会话同样适用时，不得宣称更强的自动归属。
- 同标题终端召回的既有歧义，不因远程执行自动消失。
- 未关闭 R28、R29 和完整门禁前，远程执行保持技术预览，不写入稳定发布说明。
