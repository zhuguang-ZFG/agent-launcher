# Agent Launcher 工作台界面重设计

- 日期：2026-11-27
- 状态：待用户审阅
- 分支：`docs/workspace-ui-redesign-20261127`
- 文档：`docs/superpowers/specs/2026-11-27-workspace-ui-redesign.md`

> 2026-11-27 修订：用户将并发上限从 8 个改为 6 个。下文一律以 6 为准。

## 1. 目标与约束

把主窗口做得更好看、更好用。日常成功路径是：选项目 → 勾选最多 6 个 Agent → 按一次启动 → 主窗口变成最多 6 个真实、可交互、同时在跑的终端窗格。同一套信息只出现一次；启动后用户要在窗格里看见并操作 Agent，而不是对着配置预览。

约束：

- 最多 6 个真实 Agent 并发，不以 8 或 16 为窗格目标。
- 不修改资源阈值、CPU 默认、Job 默认或预留下限。界面只改变展示与操作合流，准入仍走现有 `ResourcePolicy`。
- 空窗格、只保活、或串行排队都不算成功。
- 本说明不授权修改产品代码，也不授权替换正在使用的安装包、全局 Terminal 配置或快捷方式。实施需另出计划并经同意。

已否决的方向：

- 主窗口继续以配置为主，窗格仍放在 Windows Terminal 里看。
- 把配置页和工作台当成对等模式、用一键频繁切换。允许从工作台回到起步页，但启动成功后的默认界面是工作台。
- 左侧始终露出全部槽位的常驻侧栏。
- 默认使用浅色主题。
- 去掉窗格最大化、始终钉死网格。

## 2. 主窗口两种状态

主窗口同一时间只处于下列之一。

**起步页**：还没有启动本组，或用户在全部结束后主动返回。只做三件事：选项目、勾选最多 6 个 Agent、启动。

**工作台**：至少有一个 Agent 已经开始启动（允许其余仍在启动中）。主体是真实嵌入终端网格。

切换规则：

- 在起步页按下「启动 N 个」，且至少 1 个开始启动，立即进入工作台，不必等全部就绪。
- 工作台里有窗格退出或被停止，整窗仍留在工作台。
- 全部窗格都已结束，整窗仍留在工作台，并提供「回到起步页」；不自动跳回。
- 用户按下「回到起步页」后回到起步页。已结束的会话进入运行记录，记录不丢。

## 3. 起步页

### 3.1 顶栏

显示产品名、当前项目短名、设置。项目短名可打开最近项目或选择文件夹。完整路径不作为标题，只放在项目名的提示里。

### 3.2 主体

项目区显示当前项目短名和「更换」。还没有项目时，引导用户选择目录或把文件夹拖进窗口。

Agent 选择是可勾选的小卡片网格，不再同时使用左侧大列表、中间槽位表单和分屏预览三套重复信息。每张卡片显示名称、本机或远程、就绪或未就绪。未就绪的卡片可见，但不能勾选；卡片上用一句话说清原因，例如找不到程序、目录无效。已就绪的卡片用点击或空格勾选。已经勾满 6 个时，再点第 7 个保持未勾选，并提示「最多同时 6 个」。

主表面不放置分屏预览，也不放置「启动选项」「组合与批量设置」「运行记录」折叠区。这些能力放到设置或「更多」里，需要时再打开。

### 3.3 底部动作条

只保留一行状态和一颗主按钮。

状态行写清：已选 N / 最多 6，以及可用资源的一句人话，例如「按当前测量，大约还可再开 2 个」。资源不够时说明原因。禁止再写「本机预览不是启动授权」这类说明作为主表面文案。

主按钮文案为「启动 N 个」。N 是当前已选且就绪、可以被这次启动纳入的数量。N 为 0 时按钮禁用，旁边说明原因：还没有选项目、还没有选 Agent，或选中的都还未就绪。

按下主按钮后，按钮文案改为「正在启动…」，并在这一次点击里自动完成资源检查。不再并排「检查资源并启动」和「等待资源后启动」两颗按钮。

如果现有策略不允许一次开满已选数量：启动当前被允许的个数，进入工作台，并写清「当前运行 X / 最多 6，还差 Y，因为……」。原因以现有策略结果为准，不因此放宽阈值。如果一个都无法启动，留在起步页，按钮恢复可点，并说明原因。

## 4. 工作台

### 4.1 顶栏

顶栏高度约 40–44px，只保留：

- 项目短名
- 当前运行数 / 最多 6（只计仍在运行或正在启动的窗格；已退出的不算运行中，但格子可以仍留在网格里）
- 内存或资源一句；平静时用次要色，紧张时改用琥珀色文字
- 「+」用于添加窗格；已经有 6 个格子时禁用，并提示已满
- 设置
- 全部结束后出现「回到起步页」

### 4.2 网格

网格里是真实嵌入终端，复用已有嵌入终端能力，禁止再用静态「启动后的样子」预览冒充工作台。

格子数量按「当前仍留在网格中的格子」计算，包括已退出但尚未关闭的格子。布局规则：

- 1 格：单格铺满
- 2 格：宽窗口左右分，窄窗口上下分
- 3–4 格：2×2
- 5–6 格：2×3

单个格子的最小舒适尺寸为宽 420px、高 240px。当窗口宽度无法舒适放下两列时，改为单列滚动，不把格子压到无法阅读或无法点击。

### 4.3 单个窗格

窗格标题条约 28–32px，显示：序号、短名、本机或远程、状态点、菜单、停止。状态点约定：运行中为绿色，启动中、等待或资源紧张为琥珀，退出为红色。

命令、完整路径和启动参数不放在主表面，进入该格菜单。

点击格体即聚焦，键盘和鼠标输入进入该终端。当前焦点窗格用强调色细描边标出。Ctrl+Tab 与 Ctrl+Shift+Tab 在窗格间轮换焦点。

双击标题把该格铺满工作台区域；再双击，或使用「回到网格」，恢复原网格。最大化是快捷操作，不是默认布局。

按下停止后，该 Agent 结束，格子留在原位，显示能得到的退出原因和「重新启动」。整窗不回到起步页。菜单中的「关闭格子」会把该格移出网格并重排；如果这是最后一格且已经结束，工作台可以空着，并突出「回到起步页」。

### 4.4 添加窗格

顶栏「+」打开短列表，列出当前项目里可启动的 Agent。选中后在网格中新增一格并启动，不回到起步页。已经在网格中且仍在运行的项目不重复添加；已经退出的格子用「重新启动」，不另开重复格。

## 5. 视觉

默认深色。浅色主题只在设置中切换，信息结构和间距与深色相同。

深色 token：

- 窗口背景 `#0E1116`
- 卡片表面 `#161B22`
- 顶栏与窗格标题 `#1C2128`
- 描边 `#2B3139`，对比要低，只用来分开区域
- 主文字 `#E6EDF3`
- 次要文字 `#8B949E`
- 强调色 `#2F81F7`，只用于主按钮和当前焦点窗格描边
- 运行中 `#3FB950`
- 等待或紧张 `#D29922`
- 退出或危险 `#F85149`

浅色主题不另做一套布局，token 为：

- 窗口背景 `#F6F8FA`
- 卡片表面 `#FFFFFF`
- 顶栏与窗格标题 `#F0F2F4`
- 描边 `#D0D7DE`
- 主文字 `#1F2328`
- 次要文字 `#656D76`
- 强调色与状态色与深色相同

圆角统一：卡片 12px，按钮 8px，窗格 10px。主文字保持高对比；次要信息才用灰色。不要把强调色或状态色铺成大面积背景。

界面字体用系统中文 UI（微软雅黑，或与 Segoe UI 搭配）。等宽字体（Consolas 等）只用于终端内容和完整路径提示。标题必须是短名，超长路径或测试用目录名要截断，悬停再显示全文。

起步页要留出空白，避免卡片套卡片。进入工作台后，把面积留给终端：顶栏和窗格标题保持上述薄高度。从起步页切到工作台用 200–250ms 的短淡入，不做夸张动画。

## 6. 键盘与焦点

起步页 Tab 顺序：项目 → Agent 卡片 → 主按钮 → 设置。空格切换当前聚焦卡片的勾选（在允许勾选时）。Enter 在主按钮可用时触发启动。

工作台中，焦点窗格必须有明显描边。Ctrl+Tab / Ctrl+Shift+Tab 轮换窗格。已有的 Ctrl+K 快捷操作可以保留，但不是完成「选项目、勾选、启动」这条主路径的必要条件。

现有自动化 ID 能迁移的就迁移；界面检查必须改到新结构，不能为了让旧检查通过而保留三套重复界面。

## 7. 错误、资源与范围

资源评估、准入和阈值保持现状。本设计只合并启动按钮，并如实展示结果。

内存和可再开数量必须来自已有测量。结果过期或未知时，写「正在检查」或「暂不清楚」，不得把空值显示成 0，也不得在没有测量依据时宣称一定能开满 6 个。

现有远程、同步、任务历史和诊断能力不删除，只是退出主表面，放到设置、更多或独立历史窗口中。Windows Terminal 外部分屏不再作为启动后的默认界面；若实现阶段仍保留作为次要出口，只能放在设置里，不能替代窗口内工作台。

本说明不重做远程协议、同步算法或 Job 记账。实现必须在干净的独立分支和工作树上进行，不得覆盖 `D:\Users\pj\agent-launcher` 工作区里尚未提交的改动。

## 8. 验收标准

实现阶段按下面的标准验收，本说明先把标准定死：

- 起步页没有分屏预览，没有三套重复的 Agent 信息，没有并排两颗启动按钮，也没有「预览不是授权」作为主表面文案。
- 在已就绪的前提下，分别启动 1、2、4、6 个 Agent 后，主窗口变为对应数量的真实可输入窗格，而不是静态预览。
- 第 7 个 Agent 勾选不上，并出现「最多同时 6 个」的说明。
- 部分启动时，工作台同时显示当前运行数、最多 6，以及缺口原因。
- 停止或自行退出其中一格后，窗口仍在工作台；该格显示原因和「重新启动」。
- 全部结束后不自动回到起步页，用户可以手动返回。
- 窄窗口改为单列滚动后，标题、按钮和窗格操作仍然可读、可点。
- 默认深色符合第 5 节的层级和用色；切换浅色后结构不乱。
- 相关界面自动化检查按新结构更新后通过。本说明提交时不改测试代码。
